# 打开 ClapGrid

插件根目录为本技能目录的 `../..`；先解析绝对路径。全程中文沟通。

1. 从当前请求或已确认上下文取得本地项目目录；缺少时询问目录，不自行挑选用户文件夹。检查 `node --version` 至少 22.13；缺少组件时报告所需 Node.js 版本，由宿主许可的安装流程处理。
2. 运行 `node <插件根目录>/dist/runtime.js status --project <目录>`，成功后核对项目目录。默认端口 48762；自定义端口须对所有命令使用相同 `--port`，并给插件 MCP 的 `CLAPGRID_SERVICE_URL` 设置相应 `http://127.0.0.1:<端口>`。
3. 服务不可达时，经宿主执行审批运行 `node <插件根目录>/dist/runtime.js start --project <目录>`。该命令会复用同项目服务；端口属于其他项目或服务时报告冲突，保留原服务。没有明确重试指令时不重复启动。
4. **审批被拒时停止启动流程**，报告“宿主未允许启动，本次操作未执行”及拒绝原因。只读状态查询获允许时可查旧服务；不得更换执行路径绕过拒绝。
5. 启动之后在独立工具调用中再次执行 status。只有核对成功才声明在线；命令成功不代表后台进程跨调用存活。宿主沙箱清理后台进程时通过正常宿主审批处理，不更改安全配置。
6. 使用 `open_in_codex`，`placement: right`、`target.type: browser`、URL 为已核对的 status.url。若返回 queued，继续检查内置浏览器；只有实际读到表格或用户确认看到才算打开成功。缺少右侧能力时报告未验证，不以外部浏览器替代。
7. 调用 `clapgrid_status` 核对服务实例和项目目录与面板一致。工具未加载时说明需安装插件并在新会话加载，不能把命令行协议验证当作宿主工具发现通过。

本入口只连接项目，不发起配音、导出或片段写入。关闭面板或 MCP 不终止服务；重开先查询原项目和任务，不重发制作请求。任务进行时保持原项目连接；其他项目使用用户明确指定的其他端口。

用户要求退出本地服务时，执行 `node <插件根目录>/dist/runtime.js stop --project <目录>`（同一端口）。有任务时返回 `kept`，默认保持服务，并提示用户可选择“中断任务并退出”。仅用户明确选择该项后执行相同命令加 `--interrupt`。`stopping` 表示已开始停止，须继续查询至旧实例离线，不把已受理当作已退出。普通 SIGTERM/SIGINT 同样默认保持正在执行任务的服务；强制终止不是退出协议。

服务重开会恢复成功结果，将未完成任务标为中断且不自动重试。导出恢复先等待旧媒体进程结束及文件清理；仍锁定时继续查询原因，不删除锁文件或媒体运行标记。用户明确重新生成或导出后才创建新任务。
