# Linux 组件准备

由 Codex 执行命令，日常打开不要求用户手动使用终端。

1. 执行 `bash <插件根目录>/scripts/runtime-linux.sh check`。退出 0 才是组件就绪；继续主流程查询服务。
2. 退出 10 表示组件缺失或不兼容。解释将安装的组件和位置，通过宿主允许的安装审批执行同脚本 `install`。自动安装范围是 Ubuntu 24.04、x86_64/aarch64；实际已验证的平台以仓库验收记录为准。已有兼容组件优先复用。
3. Node 固定为官方 22.23.3，校验内置 SHA-256 后放入 `${XDG_DATA_HOME:-$HOME/.local/share}/clapgrid/runtime/node`，不修改系统 PATH。`CLAPGRID_RUNTIME_HOME` 可指定组件根目录，须在所有调用及插件 MCP 环境中一致设置。FFmpeg/ffprobe 和中文字体使用系统软件源的 `ffmpeg fontconfig fonts-noto-cjk`，需要管理员权限。基础下载工具缺失时按错误提示通过系统包管理准备。
4. 退出 11 表示不支持自动安装的系统或架构；12 表示缺管理员权限；13 表示下载、校验、包管理或安装后检查失败。报告原始原因，解决后才重新执行 install。已完成的组件会复用；安装不会自动启动服务或制作任务。
5. 安装与后台启动是两次独立操作。宿主拒绝任何一步时停止该操作并报告拒绝，遵守主流程的审批规则。成功安装后再次 check，再继续 open 和独立 workspace-status 核对。

若首次加载 MCP 时尚无 Node，组件准备后在新会话重新加载插件工具。只有新会话实际发现工具并成功查询才算 MCP 加载通过；直接执行缓存中的脚本不等同于工具发现。完整退出期间的任务保持原有独立服务语义。
