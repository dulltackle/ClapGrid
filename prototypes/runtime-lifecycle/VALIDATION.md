# 三平台运行原型复测规程

对应 #10；这是一次性模拟任务验证，不调用配音服务。每个平台独立填写，不照搬 Ubuntu 结果。插件快照为同目录 `clapgrid-runtime-probe.zip`；安装后必须从安装缓存中的技能和脚本运行，不能用仓库启动代替插件验收。

## 环境与安装

记录操作系统及版本、架构、Codex 版本、插件版本、实际安装步骤和审批提示。记录 Python 3 是否预先存在；Linux/macOS 用 `python3 --version`，Windows 用 `py -3 --version`。缺失时记录首次组件安装未完成，安装后再试；不能把预装 Python 当作首次组件安装通过。

在安装后的新 Codex 任务中调用 `$clapgrid-runtime-probe`。记录技能能否发现、缓存路径、启动命令、右侧打开工具是否可用。打开请求 queued 只算排队，看到右侧页面才算打开成功。缺少工具或需手动打开时如实记录，外部浏览器不算通过。

## 分项体验

1. 编辑一段独特文案，确认显示已保存；关闭并重开页面，核对内容。
2. 用鼠标操作 VP8 预览播放、暂停和拖动，记录画面跳转与音频听感。不要使用无障碍点击原生媒体控件来代替鼠标测试。
3. 开始模拟任务，记录 `/state` 中的时间、PID、任务 ID、进度、状态和 locked。若已有运行任务则复用，不重复创建。
4. 单独关闭面板，稍后重开；先读取 `/state`，核对同一 PID、同一任务、进度增加，运行中仍锁定且拒绝编辑、重复启动。完成时解锁是正常结果。
5. 在任务仍运行时，完全退出 Codex，稍后重开；先读取 `/state`，再考虑启动器。相同 PID 和任务 ID、进度继续或已完成才支持旧服务存活。服务不可连接时先记录失败，不能悄悄重启后当作通过。
6. 有任务时请求普通退出，预期拒绝退出并保持任务。仅测试者明确选择“中断任务并退出”后才中断；重开显示原任务已中断且不会自动重试。服务异常退出测试也必须先取得明确中断授权。
7. 无运行任务时正常退出服务，观察页面断连提示；从技能重新启动后重连、恢复文案。分别记录默认执行环境和需要宿主审批的启动结果；必须在另一次调用中检查 `/state`，不能仅凭启动器输出判成功。
8. 重复调用技能启动器，核对 PID 和任务 ID 不变，未创建重复服务或任务。
