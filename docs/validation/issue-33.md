# #33 配音任务期间禁止切换项目与导出

本轮修复并验证配音未结束时的导出拒绝。项目切换入口尚未落实，#33 不能整体关闭；缺少入口不计为任务锁通过。

## 发现与修复

原实现将「配音任务尚未结束」放入导出任务的校验问题中，仍会受理导出、创建任务及临时工作目录。现在在创建任务之前检查配音锁，表格 HTTP 与业务 MCP 共用该拒绝行为，反馈「配音任务尚未结束，不能开始导出；允许查询和试听」。其他可执行导出的素材及设置问题继续由导出前置校验汇总。

## 自动化回归

测试边界经用户确认：实际项目切换入口、表格使用的 HTTP 导出入口及业务 MCP。项目切换因入口不存在未新增伪造接口测试。既有业务接口测试同步调整为新验收要求。

- `tests/speech-export-lock.test.ts`：使用真实 SQLite、服务、MCP 工具和 FFmpeg；仅替换外部配音供应商响应。先为独立项目准备有效视频、MP3 和字幕设置，实际导出成功，证明条件有效。随后生成配音，通过 HTTP 和 MCP 请求导出，断开并重连表格后再次请求，均应明确拒绝；导出任务和目录不变，项目、服务实例和配音任务身份保持，查询和已有音频读取可用。
- 分别覆盖配音成功、供应商明确失败（401）、服务关闭后重开恢复未知结果。恢复后无自动导出或配音重试；修改文案后手动导出按最新输入反馈「配音待更新」，证明前置校验恢复。
- `tests/export-tasks.test.ts`：通过既有业务接口同步检查 `accepted`，下一事件循环检查 `running`，两个阶段均拒绝，任务列表为空且未创建导出目录。配音结束后可再次受理导出，汇总缺失视频和设置问题。
- 红绿验证：新 HTTP/MCP 用例在原代码上因 `Missing expected rejection` 失败；提前拒绝后通过。HTTP 用例的提交返回值为 accepted，但后续拒绝断言明确等待 running，不将其冒充为真实 HTTP accepted 窗口验证。

## 项目切换缺口

`src/runtime.ts` 只提供 start/status/stop。已有服务的项目与指定目录不同时，无论是否存在任务，均返回「端口上的服务属于其他项目，请保留该服务并明确选择其他端口」。表格与业务 MCP 也未提供切换项目入口。这个身份校验没有依据配音状态作出拒绝，不能证明任务锁阻止切换，更不能证明任务结束后切换恢复可用。

#26 已关闭并不等于 #33 的项目切换开始条件满足。按本事项「只补齐锁验收，不重复实现完整导出或生命周期功能」的范围，本轮不自行设计项目切换功能。
