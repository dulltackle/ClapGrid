环境：Linux，Node.js 22.23.3。本次使用独立测试项目，不修改用户制作项目。

最终结论：Linux 的真实配音／导出跨 Codex 退出、服务中断及实际重启恢复均已完成验收。原始任务日志、开机标识、文件摘要和媒体验证结果随本文保存；Windows/macOS 的平台交付不在本次实测范围内。

## 自动化验证

- `tests/lifecycle.test.ts`：HTTP 退出请求绑定服务实例；有配音任务时默认保持服务和项目锁，仅明确中断退出后停止。重开保留任务标识，不自动重试。批量部分完成保留成功音频，运行项显示结果未知，尚未发送项明确提示中断；同一操作重放不新增供应商请求。
- `tests/lifecycle-export.test.ts`：使用真实 FFmpeg、合成视频与模拟供应商返回的 MP3 完成实际导出。服务进程被 SIGKILL 后重开，读取操作系统进程记录确认旧 FFmpeg 已停止，再核对任务中断、工作目录删除和既有成片字节不变。修改文案后重新导出因最新配音待更新而失败，证明没有续用旧导出快照。
- 上述崩溃测试在接入媒体守护进程前失败：重开解锁时旧 FFmpeg 仍存活。接入后同一测试通过。
- `tests/lifecycle-runtime.test.ts`：构建真实后台入口和媒体守护进程；启动命令退出后服务可查询，重复启动复用相同实例、PID 和项目身份，其他项目被拒绝，正常停止后重开保留项目身份。
- 服务协议与媒体进程验证属于自动化证据，不等同于退出 Codex 后的宿主验收。

## 恢复边界

媒体守护进程自身异常时，持久化活动标记阻止不安全恢复；不会删除可能仍被写入的文件。Linux 通过开机标识识别前一次关机的遗留标记。Windows/macOS 的宿主生命周期和关机标记恢复尚未验证，不代表三平台验收通过。
