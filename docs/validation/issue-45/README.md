# 工作空间变化与后台任务持续运行

## 绑定失效修复

原绑定只签名对话身份，回到原目录后旧 URL 会恢复可用。现在服务为每个对话保留一个绑定代次，工作空间不符或宿主查询失败就撤销该代次。旧面板的 URL 此后永久拒绝；经打开入口或业务 MCP 再次核对宿主身份后才签发新代次。

同一有效代次在反复 MCP 调用时复用，不逐调用积累绑定，也不会因为 MCP 调用而断开合法面板。服务重启继续使用新实例签名，不能复用旧实例绑定。绑定代次撤销仅影响访问和面板连接，不结束项目后台任务。

状态读取保留服务返回的关闭重开提示，面板展示当前失败原因及重新核对工作空间的指引；连接状态不可用时新增和导出入口禁用。服务仍在所有业务读写、任务提交及勾选端点核对绑定，不能仅靠 UI 提示绕过。

- `tests/workspace-task-continuity.test.ts`：真实项目 HTTP 服务和 MCP、打包打开入口，配音供应商使用可控替身。旧任务已受理后改变宿主目录，旧面板断开、旧读写/勾选/任务提交拒绝；新目录连接独立项目；回到原目录重新核对后仍见同一任务、锁仍保留，供应商只调用一次。宿主不可查询时撤销绑定，恢复后要求再次打开；旧任务成功终态、音频可读后才解锁。
- `tests/editing-panel.test.ts`：真实 React 面板保留失败原因和关闭重开提示，状态失效后新增、导出禁用。

宿主 app-server 和供应商在上述测试中是边界替身，不能当作实际宿主或真实供应商验收。

## 实际宿主已有证据与范围

参见 [#42 验证记录](../issue-42/README.md)：Linux、Codex MCP 客户端 0.160.0、插件 `.2` 与 `.3` 曾实际完成同一聊天目录往返、旧面板与 MCP 拒绝、新目录项目打开；记录包含项目与实例身份。那次没有配音或导出任务，因此不能证明任务期间的真实往返，也不能证明本次代次撤销修复已经部署。

宿主只提供持久聊天 `thread/read` 的本地 cwd，本实现逐业务调用和长连接心跳核对，不订阅工作空间变化事件。只能处理已观察到的目录变化或核对失败；两次查询之间快速移出并移回且未被观察的变化、移动到下一轮之前 cwd 同步窗口仍无稳定通知保证。实际目录无效时拒绝；移出桌面项目但保留 cwd 的额外语义按 #48 延期。

尚未执行本版本实际宿主的任务期间往返、真实供应商继续完成和旧 URL 永久失效验证。不得勾选这些验收，不替代 #33 真实配音期间导出锁验证；最终证据需汇入 #30。

与 #44 集成后补充回归发现：仅撤销绑定、等待心跳清理会让新代次短暂读取旧面板勾选。现改为撤销时立即清理该代次的表格与编辑会话，不影响新代次连接。回归验证新绑定读不到旧勾选，旧修改权立即释放，原任务锁保持。

## 独立审查后的在途编辑修复

OCR 通过 HTTP 复现：旧代次 Codex 视频导入在等待媒体处理时被撤销，随后仍能提交素材。该发现有效，已补充 `tests/workspace-inflight-edit.test.ts` 的打开入口与 HTTP 回归，覆盖用户和 Codex 的导入、画面关联、导出设置，以及无额外轮询时提交前才观察到目录失效。

普通修改权现在区分“已撤销”与“清理完成”：撤销会中止在途编辑、阻止提交，但媒体进程退出和临时文件清理完成前仍保持项目占用。Codex 在途请求也登记绑定代次；所有异步编辑路径在提交前再次核对其修改权关联的宿主绑定。空闲编辑会话仍立即释放，在途编辑不提前解锁。此变化不取消配音或导出后台任务，不改变自动重试策略。

原有“整批结束返回已释放状态”回归曾发现成功响应快照仍含清理保留占用；现于业务处理结束后、生成成功响应之前结束清理保留并释放修改权，受影响测试复验记录保存在本轮运行日志中。
