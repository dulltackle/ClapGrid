## 覆盖边界

`tests/lifecycle-export.test.ts` 将原先固定端口、开发服务入口改为打包后的 `runtime open --workspace --thread`。服务和媒体守护进程真实独立启动，HTTP 使用入口返回的完整绑定地址，stdio MCP 使用当前聊天元数据自动发现。测试只替代外部宿主 `thread/read`；视频、音频夹具与导出使用真实 FFmpeg，夹具配音通过供应商响应替身准备，不向真实供应商提交。

- 受理导出后关闭表格和 MCP，另一个同工作空间聊天重新打开，项目/服务/任务身份保持。新 MCP 查询到同一任务，最终成片字节和路径一致。
- 一个任务渲染期间改变模拟聊天目录，旧绑定拒绝而另一合法聊天仍查询同一运行任务和锁；回到原目录必须重新打开，旧绑定不能复活。测试暂时暂停本次 FFmpeg 进程以固定观察窗口，结束观察后恢复其运行。
- 默认 SIGTERM 保持运行任务及锁；SIGKILL 服务后通过正式 open 恢复，同项目、不同实例，旧绑定失效。旧媒体必须退出，未完成任务标记 interrupted、工作目录清理后才观测到解锁；没有新增导出任务。
- 已完成成片和配音在新绑定下仍能访问且字节一致。已有输入变化会使显式后续导出反馈“配音待更新”，不会自动补生成。
- 媒体守护进程异常退出且子进程状态尚未确认时，打包 open 拒绝恢复并在 service.log 保留原因，工作目录和历史成片保持。测试清理仅回收测试自身进程；没有删除运行标记来绕过产品恢复。

`tests/lifecycle.test.ts` 的批量部分完成后中断用例也改为工作空间项目：服务使用外部供应商响应注入边界，再由打包 open 自动发现。成功音频保留，正在请求的项提示未知/可能已计费，未发出的项提示尚未发送；重新打开保持项目身份、改变实例，并且在重放前已经只有原来三个任务。相同请求重放返回原批量操作，供应商调用不增加。

仍复用 `lifecycle-runtime.test.ts` 的旧后台入口兼容性、`workspace-sharing.test.ts` 的绑定入口多聊天配音任务/去重、`workspace-task-continuity.test.ts` 的目录改变时已受理配音继续；不重复创建同类测试，也不扩大为项目切换入口。
