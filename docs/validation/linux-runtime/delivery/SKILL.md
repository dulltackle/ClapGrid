# 打开运行验证原型

这是一次性模拟任务验证，不调用收费服务。全程中文沟通。原型资产位于本技能目录的 `../../scripts`，从安装缓存解析绝对路径后执行，项目数据位于系统临时目录。

## Ubuntu 入口

1. 运行 `bash <脚本目录>/runtime-linux.sh check`。成功后进入状态查询；返回 10 表示缺少或不兼容的 Python，进入首次安装。其他错误先报告具体原因。
2. 首次安装：说明将从 Ubuntu 系统仓库安装 Python 3 及依赖。由 Codex 按宿主执行审批机制运行 `bash <脚本目录>/runtime-linux.sh install`，无需用户手动运行终端。返回 0 才算组件就绪；返回 11 表示发行版未支持，12 表示需系统管理员认证，13 表示安装失败。向用户呈现具体错误与下一步，修复原因后可重试同一 install。系统认证由用户通过宿主允许的界面完成，不读取密码、不绕过拒绝。组件安装不会启动服务或任务。
3. 先运行 `bash <脚本目录>/runtime-linux.sh status`。成功则复用其中的原服务与任务，直接打开表格。返回 20 时根据错误区分连接失败和其他服务占用；身份或项目不匹配时保留原服务，选择不冲突的端口后再启动。
4. 没有在线目标服务时，由 Codex 经宿主执行审批运行 `bash <脚本目录>/runtime-linux.sh start`。启动后必须在另一次工具调用中运行 status，核对 PID、项目和任务；单次启动器成功不代表后台进程跨命令存活。默认沙箱曾清理后台进程，按宿主许可机制处理，保持安全设置不变。
5. 安装或启动审批被拒时，脚本通常没有执行：说明“宿主未允许安装／启动，本次操作未执行”，保留拒绝原因，不改用其他提权或执行路径。若 Python 已就绪且只读查询被允许，可查询 status，区分旧服务仍在线与当前未确认在线；未运行查询时不推断服务已停止。等用户明确要求重试且宿主许可后再执行。
6. 用宿主 `open_in_codex`，参数 `placement: right`、`target.type: browser`、URL 为 status 返回值。返回 queued 只记排队，实际读取页面或用户看到页面才算成功。缺少该能力时记录当前会话无法完成右侧打开，不用外部浏览器代替验收。

start 和 status 的 `--port`、`--project` 必须一致。默认仅监听 `127.0.0.1:48761`；验证其他端口时给两条命令同时附加参数。日常只需用户调用本技能，由 Codex 完成检查、复用／启动及右侧打开。

## 其他平台

Linux 其他发行版可使用已有 Python 3.9 以上执行 check/start/status；自动安装仅支持 Ubuntu 24.04。macOS 检查 `python3`、Windows 检查 `py -3`，组件已存在时运行 `prototype.py`，使用只读 `runtime_status.py` 独立检查，再按上述右侧打开和审批规则操作。缺组件时报告对应平台首次安装尚未交付；不得套用 Ubuntu 安装命令。

## 生命周期验证

记录系统、Codex、Python、插件版本、实际命令及各项结果。安装后的新会话调用本技能才验证技能发现；从仓库手动调用不能替代安装验收。

退出 Codex 前保存 `/state` 中 PID、任务 ID、进度、时间和 locked，确认任务仍在运行且留有充足时间。重开后先运行 status，核对原进程和同一任务继续或完成，再考虑启动器。已有运行任务时复用，不重复创建。服务不可达先记录失败，不能重启后宣称旧进程存活。

模拟任务持锁期间编辑与重复创建应被拒绝；普通退出应保持服务。只有用户明确中断才发送中断请求。无任务时可以正常退出服务。原型不覆盖真实配音、导出或普通编辑修改权。

媒体使用 VP8/Opus 预览副本；原生媒体控件的无障碍点击在测试宿主上曾导致崩溃，使用真实鼠标或请用户体验。其他平台、音频听感与首次组件安装逐项记录，不用已有 Ubuntu 证据代替。
