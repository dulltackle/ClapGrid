# 测试执行者试点记录

本记录保存 [#148](https://github.com/dulltackle/ClapGrid/issues/148) 试点的方法、实现取舍和证据读取方式。设计采纳见 [ADR0009](../adr/0009-test-executors-and-cumulative-evidence.md)，当前命令及恢复操作见 [检查与正式验收](../agents/verification.md)。本记录不以设计、代码审查或开发样本代替最终性能和正式验收结论。

## 固定覆盖与对照

候选直接开发依赖固定 Vitest 5.0.5 与 Playwright Test 1.64.1，并以 lockfile 安装。试点保留 16 项逻辑、4 项真实 HTTP/SQLite 和 14 项固定 UI 场景；UI 中 12 项使用真实 Chrome，2 项验证生产同源 CSS。每个场景及原生快照对应 `scripts/test-pilot-baseline.json`；唯一归属、scope 和严格政策对应 `scripts/test-inventory.json`。未迁移测试与生命周期/验收专项继续 Node 原生测试器，原生对照独立保留，不在常规完整检查重复调度。

统一证据同时核对计划、原生注册和实际完成事件、nonce、执行者版本、完整文件/用例集合、原始日志及来源摘要。缺报告、零收集、未捕获错误、失败/取消或集合缺口均失败；UI 逐例要求实际 passed，无 skip、todo 或 retry 放行。预检和集中复验仅在当前完整运行的私有账本、源码/配置/环境匹配时累计，引用原证明而不声称再次执行。默认新运行不得复制旧成功报告取得资格，显式历史复用仍核对原始来源与原完成时间。

## 完整准备协议

### 内容身份与测试启动准备

`scripts/source-identity.json` 显式选择 `sha256-merkle-v1`。每次采集仍枚举代码检查范围内的 Git 跟踪文件与未忽略新文件，读取当前完整内容；路径、文件/链接/缺失类型、执行位、字节长度和内容参与身份。符号链接计入链接文本，跟踪的忽略文件仍在范围内。未知类型、读取失败及采集期间算法配置变化均拒绝；不以 mtime、历史摘要或上次通过代替本次内容读取。schema 2 以 `code-check-v1` 显式排除 `docs/productions/`、`docs/validation/`、`docs/design/`，同步用于指纹、选测依赖图和 watch。未知路径、模板和真实测试 fixture 继续纳入；无配置或 schema 1 的历史检出保留原全仓库范围，旧范围报告不转换为新证据。范围决定见 [ADR0010](../adr/0010-code-check-input-boundary.md)。没有该配置的旧检出继续原 `sha256:` 协议，不将旧记录伪装成新算法。

同步和异步采集遵守同一内容规范。异步 API 默认使用 `min(4, availableParallelism())` 个短期源码 worker，可显式请求 1 至 8 个；实际线程数受文件数量限制。文件尺寸仅用于本次负载分配，不充当内容身份。worker 仅加载内建模块，使用空环境及空 `execArgv`，不继承项目预载或测试 child 的字节码缓存。每次重新核对文件并读取实际字节；普通文件采用不跟随链接的 descriptor 打开及类型/身份检查，避免中途替换为 FIFO 或链接导致挂起。

每个 worker 的随机 nonce、消息唯一性、完整成员集合、错误和实际退出都需核对；取消或异常也终止并等待全部本次线程，不能提前释放工作树锁。初始身份采集取消产生 `cancelled` 和退出 130，未完成的身份留空，不借用历史身份。起止身份相同只证明两个边界的结果相同，不构成文件系统原子快照，也不保证发现未被观察到的修改后恢复。

单一 Vitest 执行者可将固定纯框架预加载与本次完整源码读取重叠；本次身份完成前不加载项目配置、setup 或测试文件。普通管道以本次随机 executionId 放行，早退、错误消息、源码失败及取消均回收本次子进程和线程。非空 `NODE_OPTIONS` 不能证明只有纯框架，保守先完整读取再串行启动。该优化不减少选中测试、类型检查、生产构建或最终来源校验。目标缺少新增 bootstrap 或缓存模块时，保留其原有配置/环境身份形状；不能仅因宿主更新而要求历史目标补齐当前文件。

### 浏览器准备与同步编译输入

固定核心仍为 5 个文件、14 个场景，其中 12 个使用真实 Chrome。只有 `segment-note-layout-panel.test.ts`、`table-controls-panel.test.ts` 与 `wide-panel.test.ts` 显式开启文件内并行；`speech-cell-layout-panel.test.ts` 的 3 个场景与 `style-collisions.test.ts` 的 2 个场景保持 serial。CSS 文件使用同一扩展 test 的 worker fixture pool，避免另起一个只执行 CSS 的框架 worker；CSS 不请求 `panel` 或 `managedBrowser`，纯 CSS 范围无需可用浏览器，也不创建受管 Chrome、context 或 profile。入口已有的版本探测边界仍可能存在。

并发 1/2 入口继续保留，不启用全局 `fullyParallel`，不扩大生命周期专项或未知扩展的并行范围。每 worker 同时执行一个用例，可复用该 worker 的 Chrome；每个浏览器用例重新创建独立 context、page、DOM/storage 和专属目录，结束后完整回收。原场景脚本、等待、真实键鼠和行为断言保留，重试为零。worker 骤死、超时、取消和拥有者退出仍通过原进程组及具有身份凭据的资源清理机制收尾。

测试 JS bundle 保持开发环境、IIFE 和 automatic JSX，使用 esbuild `minify:true`、`keepNames:true`，并以显式构建选项及版本化 key 区分产物；保留实际名称、错误信息与执行结果回归。CSS 的 Vite/Tailwind 仅在缓存未命中的真实编译回调内载入，载入后再核对绑定；构造、读取、编译前后及输出前的工具和环境检查都保留。冷/热命中只是准备路径变化，每次仍执行实际选中场景。

编译缓存仍核对完整源码、扫描成员、实际 import 及解析绑定、配置继承、package/lock、真实工具与已安装依赖内容、资源、构建选项和环境。只能在一个连续同步、封闭只读边界内共享本次实际读取；声明式输入计划不会把任意 callback 认证为只读。兼容的任意输入 callback 先在边界外执行，再重新读取当前输入。compile、await、产物恢复或下一次 helper 调用均重新建立边界。

私有读取边界按角色和准确路径保存当前读取，已取得且末端非链接的 lstat 可供同边界 stat 使用；链接仍实际 follow-stat。Linux native realpath 失败回真实 JS realpath，其他平台保留原路径。完整 fingerprint 保留 schema 3 原连续 frame 与原 SHA256 字节流。只有同边界完全相同的投影，或此前成功投影的准确有序前缀，才可复制私有 Hash 状态后继续消费原 frame/bytes；不拼接工具摘要，不用叶摘要替代连续 SHA。新状态直到整个投影成功才发布，失败不留下可复用成功状态；finally 关闭并释放全部私有字节、Hash 和索引。Buffer、Hash 或可执行 collector 不向任意调用者暴露。

这不是跨 view 的工具快照、通用历史投影 LRU 或历史通过复用。下一边界仍重新枚举、核对元数据、读取完整当前 bytes；未裁剪工具、依赖、源码或资源范围。未知配置/工具布局、损坏缓存和不稳定输入继续真实构建；进程已载入的工具字节变化仍要求重启。缓存原子发布、并发 worker 和另一工作树隔离规则继续适用。

### 构建环境与固定工具默认值

受构建键覆盖的环境值包括 `NODE_ENV`、`NODE_OPTIONS`、`ESBUILD_BINARY_PATH`、`BROWSERSLIST` 及其前缀变量、`TAILWIND_*`、`VITE_*`。入口、输入回调/读取后、真实编译的 await 恢复、热命中返回与发布前均重新核对；helper 外层 await 返回、写产物前还要验证模块私有结果身份。观察到变化后不消费或发布旧环境标签的字节；恢复原值不能抹掉已观察漂移。不承诺检测从未观察到的瞬时变化后恢复。

固定 Playwright 冷 transform 路径会采用 `BROWSERSLIST_IGNORE_OLD_DATA='true'`。浏览器入口仅在调用者未定义时显式补齐该默认，向实际阶段传递，并在 checkUi finally 恢复调用者原 undefined、显式值或空字符串。dispatcher 只为选中 Playwright owner 或原生 UI 参考的集合补齐，直接 Playwright 入口同样在身份与 child 启动前确定；普通 Node 子集不新增此默认。原生与候选对照使用相同条件。

该变量完整参与缓存身份，不因默认值而豁免漂移。入口保留显式值；固定第三方 Playwright 自身冷转换仍可能无条件覆盖它，不能把预热传播测试扩展为任意第三方冷转换保证。代码不悄悄还原第三方行为，实际构建/消费窗口观察到的变化仍由同一环境 guard 拒绝。direct CSS helper 的 undefined、自定义及空值冷/热行为另有真实回归。

### Node 字节码缓存

已采用 `scripts/node-compile-cache.mjs` 的目标，在未显式设置 `NODE_COMPILE_CACHE` 或 `NODE_DISABLE_COMPILE_CACHE` 时，仅给单次受控测试 child 派生默认目录：当前 canonical 工作树的 `node_modules/.cache/clapgrid-node-compile-v1`。不修改父 `process.env`，不给父 main、源码线程或普通非测试 stage 自动开启。Node 原生、Vitest 与 Playwright 的测试 child 使用同一策略；UI 原生/候选测试阶段条件一致。

显式 `NODE_COMPILE_CACHE` 自定义路径、空字符串以及 `NODE_DISABLE_COMPILE_CACHE`（包括空字符串）都按原值保留，不以自动默认覆盖。需要关闭缓存的对照可显式设置 `NODE_DISABLE_COMPILE_CACHE=1`；需要独立冷目录时显式指定新的空 `NODE_COMPILE_CACHE`，热条件复用同一目录，并保留实际请求/运行环境记录。不要将字节码文件存在称为已命中或测试已通过；冷、热、同长且还原 mtime 的源码改变以及损坏目录仍须实际执行当前内容。

watch 的 AsyncLocalStorage 派生链关闭自动默认，并向实际子孙传播已确认的 watch 控件；同进程独立任务不受该异步链影响，用户显式请求仍保留。watch 不通过改写全局 env 关闭其他任务，也不因框架进程复用取得跨轮通过资格。

自动来源标记只用于 spawn 前重派生：切换工作树或正式验收独立检出时，默认目录按实际目标 canonical root 重算；来源不完整、伪造或路径别名不符明确拒绝。旧目标不存在该模块时不继承宿主自动默认，也不新增目标的配置/环境身份字段。正式任务 key 记录显式请求与 watch 策略；实际执行身份记录目标有效策略。缓存只保存 Node 编译数据，不替代源码/环境、nonce、原生报告、类型检查、真实测试或独立 `npm ci`。


### 取消与轮末资源边界

实际拥有者记录已核对的祖先身份。合作取消仅用于已登记命令组中、当前 PID/birth/namespace 与祖先 token 关联一致的拥有者，socket 服务器对请求的 root/PID/birth/namespace 与内存身份核对；未确认的控制通道不取得取消另一工作树的资格。direct/npm 同组拥有者与独立后台 worker 的保证分别由对应真实回归记录，不能互相代替。

watch 的实际拥有者在轮末清理资源前，按当前 token 和出生身份停止全部本次已登记组，并再次确认退出。继承同树上下文不取得清空整个拥有者组的资格；身份变化或未知组保留现场。原资源 marker/路径/完成证据检查继续执行，取消监听覆盖组、资源及锁的整个清理过程。

## 测量方法

正式比较固定同一候选提交、完整行为覆盖及同机工具环境，原生与候选各至少三次，取中位数。记录 Node/npm、锁定执行者、实际 Chrome 命令/版本、OS/CPU、字体与相关环境；显式列出并发负载。最终采样期间控制并发重任务，已有并行负载的开发记录仅作诊断，不重新标为静默正式样本。

逻辑、真实 HTTP/SQLite 与 UI 分开测量。UI 使用包含类型检查、测试、生产构建和清理的完整入口，明确并发 1/2；每个条件分别设置独立空目录的冷缓存与复用目录的热缓存，并核对实际命中。原生与候选使用同样 helper 和默认环境，不能把共享构建缓存收益全部归因于新执行者。Node 字节码缓存同样明确关闭、独立冷目录、复用目录及显式控件，缓存文件存在不作为命中结论。


最终默认策略测量仅由生产入口给测试 child 开启字节码缓存，不为 npm、父 main、类型检查或构建额外注入 `NODE_COMPILE_CACHE`。每个原生/候选、组别、并发与轮次分别建立冷/热 pair；默认路径的冷条件在无活动任务时将本次拥有的旧缓存正常改名留存，热条件紧接同一 pair 复用实际默认目录。显式全链 `NODE_COMPILE_CACHE` 或关闭缓存仅作另列诊断，不能称为生产默认。

这里的“冷”仅指该 pair 的浏览器构建缓存和 Node 字节码目录。框架 transform 缓存沿用正常路径及已有内容，操作系统页缓存未清空；记录这些条件与控件，不称为全框架或整机冷启动。若使用 50ms `/proc` 进程树采样，RSS 是已观察进程的同时求和，可能重复共享页；短进程、间隔内峰值及早期 reparent 可能遗漏，CPU 也仅为已观察下界，不能称为精确 PSS 或完整内核峰值。

保存实际命令、提交/tree/起止内容身份、预期/实际场景、统一与原生报告、原日志、进程/worker/Chrome 实际收尾和资源记录。阶段包括源码和工具输入核对、lookup、真实 build、原子发布、框架/浏览器启动、交互及清理；最终以完整入口 wall-clock 为准。并发场景之和不是 wall 占比，watch 热轮不替代默认单次，局部反馈和测试子入口不替代完整正式验收。

预算保持 ADR0009：逻辑不超过 1.5 秒，真实 HTTP/SQLite 不超过 2.5 秒，14 项 UI 固定核心完整入口不超过 35 秒。是否满足这些预算必须由最终固定提交的实际三次对照得出；本文件不预填达标结论或全套加速比例。

## 正式证据与交付

最终源码和文档在正式执行前固定到同一提交。完整正式验收独立检出，实际执行 `npm ci`、强制预检、完整类型/测试/生产构建和源码变化检查，并核对原生/统一/累计证明；开发依赖目录恢复、局部回归与独立审阅不代替这些步骤。观察者退出不终止实际任务，复连保留真实任务身份；取消及异常恢复沿既有工作树拥有者、token、组和资源身份规则执行。

最终采样和正式验收完成后，在 [#156](https://github.com/dulltackle/ClapGrid/issues/156) 写回固定提交、原始证据位置、各条件样本及中位数、覆盖与差异、实际退出/清理、正式验收任务来源及未完成项。记录必须区分“代码可审”“受影响开发检查通过”“性能预算结果”和“完整正式验收结果”。结果外部写回不改变受验 HEAD；有新增变更则重新固定并按影响执行。

交付报告分别说明源码、独立检出安装/正式检查、本机插件安装包与实际宿主。该试点不自动安装/更新本机插件或发布；`npm ci` 是受验检出的依赖安装，不是插件安装。构建成功和受控 Chrome 场景通过也不证明 Codex 已加载该插件。只有另行取得实际 MCP/服务/面板与 plugin:verify 的宿主证据，才能声称实际宿主已更新可用。

本轮没有改变项目、口播片段或画面说明等业务术语，因此不为检查器私有实现扩充 GLOSSARY。编译字节复用与“证据复用”区分：后者继续保留原来源和结论时间，不冒充新执行或新验收。
