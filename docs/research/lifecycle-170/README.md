# 检查生命周期原生退出确认（#170）

对 `2a5bcc4` 的真实 check、显式 watch 和固定提交验收小仓库入口测量，正常子命令退出仍多次启动 `ps -A` 扫描整机进程组。Linux 现在先由 Node 的 `process.kill(-pgid, 0)` 查询整个登记组；仅 ESRCH 表示组已不存在。出生身份、拥有者绑定与命名空间守卫保留。组长先退出而孙进程还在、僵尸组及其他可见组继续走原来的完整扫描；EPERM 等未知错误不能当作清理完成。

## 测量

同机 Linux x64、Node 22.23.3、固定锁定依赖、文件并发 1、`NODE_DISABLE_COMPILE_CACHE=1`；协调其他检查暂停后分别三次，没有并行 CPU 检查或浏览器运行。命令、原始 TAP 日志 SHA256、实际五项名称与样本见 [测量索引](measurements.json)，原件由此次 implement-161 外部资源记录保留。每次均实际执行开发 check 两项、watch 启动/互斥/停止一项和独立检出安装与 check 两项；5/5 passed，零 skip/todo。

| 完整代表组 | 第一次 | 第二次 | 第三次 | 中位数 |
| --- | --- | --- | --- | --- |
| 基线 | 8.794 s | 8.456 s | 8.403 s | 8.456 s |
| 候选 | 6.585 s | 6.598 s | 6.609 s | 6.598 s |

各入口中位数（来自原 TAP 独立用例）：开发 check 0.975→0.605 秒，固定提交检出/安装/check 2.598→2.105 秒，watch 无变更启动/互斥/取消 0.829→0.755 秒。第二份独立 check 与固定提交案例分别为 1.005→0.622 秒、2.612→2.106 秒。收益主要来自各检查阶段正常结束后省去重复整机扫描，watch 安全回收等待不缩短。

代表组中位数缩短约 22.0%。该数值只对应上述公开入口小仓库，不代表 PR 全量或浏览器业务收益，也不把不同环境的历史 CI 时长作对照。

## 保留的最小拥有权适配与操作

- `check`、`check:ui`、`check:preflight`、`check:failed`、显式 watch 与 `verify` 继续共享真实工作树锁，不同工作树隔离。显式取消仍通过原 token 控制通道，等全部登记组与浏览器资源回收后才释放锁。
- `check:related:watch` 每轮启动新的单次入口并由父拥有者独立核对范围、nonce 与真实报告；闲置保持锁，没有输入不自动重试，失败待办保留并集中复验。
- `verify -- start --revision <提交>` 仍创建独立检出并执行该提交的 `npm ci` 与完整 check。`status/wait --run <runId>` 只观察原任务，观察终端退出不取消 worker；显式取消使用 `verify -- cancel --run <runId>`。
- `check:stop` 仍核对命名空间与出生身份；跨空间不可见 PID、控制通道不可达或未知拥有权不能清锁。Windows/macOS 的原路径保留，本次只在 Linux 验证。

没有删改任何旧场景、范围、超时、重试或 PR 门禁归属；只删去已由原生接口确认不存在组时的重复外部准备。不把 npm 脚本内联，不合并 watch 子轮或后台 worker，因为独立进程状态和观察者/拥有者分离是公开生命周期承诺。服务 runtime/export 有各自真实进程所有权边界，不为统一执行框架改写。

新增公开 CLI 回归在外部 `ps` 不可用时实际执行完整小仓库 check，观察成功退出和锁释放；它验证原生退出确认兼容行为，不绑定内部调用次数。原有 check-runner、check-watch、verification-jobs 及 test-evidence 全集覆盖取消孙进程/Chrome、拥有者异常、跨树隔离、观察者退出、源码失效、预检累计、历史证据损坏、失败待办与严格 UI。公开 test-runner 的四文件全集定向回归 125/125 passed，零 fail/skip/todo，原 session 已正常退出；项目 typecheck 通过。原始统一 JSON、原生事件 JSON 与 TAP、执行和收尾记录由 run.json 保留；固定候选完整验收、最终 PR 全量与 CI 对照由集成阶段完成，不能由本代表组代替。
