# 两种重叠配额的故障与资源边界（#188）

沿用 [#187 的三个原文件资格](../native-overlap-187/README.md)，不扩大资格集合或改变默认 `serial`。公开完整入口仍为 `npm run check -- --execution overlap-1+1|overlap-1+2`；Vitest 保持 forks、单 worker、文件串行、isolate、retry 0，Playwright 分别请求 1/2。直接测试、预检与集中复验没有新增重叠权限。

## 迟到登记反例与修补

已存在的嵌套拥有者在祖先取消后、首个已登记组的停止等待中，仍可能产生必须回收的后代。原实现把 `cancelled` 祖先当作不再绑定，导致迟到组只登记自身；最终清理又只消费一次组快照。真实 CLI 反例显示根锁已释放，但迟到组仍为 S 态，且其出生身份与原登记完全匹配。这是资源归属漏洞，不是普通失败或历史未知进程。

`scripts/check-lifecycle.mjs` 现在分别判断祖先绑定与是否仍可启动任务：已取消但完整 root/token/pid/birth/namespace 未被替换的祖先继续接收迟到组登记，同时发出取消；新的独立 `withCheckRun` 仍在入口拒绝。祖先被替换时不写入其登记，不把新采样 PID 当作原任务。

显式 drain、普通拥有者 finally 与异常停止恢复均重新读取登记，停止当前快照后继续收齐后到组。每个异步边界重新核对拥有者；普通 finally 也使用完整绑定。资源清理与控制通道关闭后的最后检查再次核对全部组及资源，全部结束才解锁；未知或变化的身份保留锁和现场，不以删除登记取得通过。

## 公开入口验证与证据

`tests/test-evidence.test.ts` 新增 34 项：两种配额各一项原生配额/完整集合检查、15 种真实故障，以及一项迟到登记/独立工作树取消。它们使用真实 CLI、原生执行者和故障后的实际 `check --failed`；同名受控夹具仅证明编排与故障边界，不替代原文件资格。

| 故障 | 观察边界 |
| --- | --- |
| 普通断言失败、worker 异常退出、未捕获错误、零收集 | 原生报告及实际退出；另一侧仍收集完整用例，retry 0 |
| 报告丢失、截断、原件篡改、错 nonce、漏文件 | 成功退出不能代替来源、身份及完整集合校验 |
| 源码变化、累计原生来源损坏 | 当次身份或旧阶段来源失效，不能留下完整通过 |
| UI skip/fixme、缺浏览器 | 严格 UI 必须实际执行；Playwright fixme 原生记为 skipped，不冒称 todo |
| 重复执行归属 | 在调度前拒绝不完整清单 |

全部故障修复为当前源码后再次实际运行集中复验，只有成功才清除失败待办。真正的 UI `todo` 语义继续由原有 all/rows 及冻结旧生产者的严格政策回归覆盖，保留其原身份与来源。

迟到取消在真实重叠入口中启动 Chrome、FFmpeg、已存在嵌套拥有者及独立子测试任务；取消请求后，在首个组的 drain 等待内登记新的 detached 子组与 Playwright 资源。原件保留取消标记、三层祖先登记、原 group birth、全部后代退出、资源 `groupsEnded` 清理及 130/解锁结果。另一棵真实 Git worktree 同时运行独立任务，取消窗口后继续产生 heartbeat，并按自己的正常完成信号退出；最后通过 Git 正常移除该 worktree。红测也只通过原 root/nested 控制入口按原登记恢复，保留反例原件。

受影响回归覆盖检查拥有者/取消、watch、后台验收任务、UI 入口及 Playwright 资源恢复，包含未知/替换绑定保锁、旧 token 拒绝与强杀恢复。原有 #187 七项新增测试和旧行为回归保留。

外部证据位于同次 `clapgrid-174-20261018/188/`：历史红测与夹具开发失败单列，最终检查、当前实现的两个原文件资格轮及独立审阅分别索引。原文件 `export-tasks` 的 18 项、`audio-panel` 的 3 项与 `video-panel` 的 11 项在修补后两个配额下重新运行；每轮保留 native、nonce、实际进程归属和清理，并独立计算每个取得资格文件的逐例时间交集。它们是资格/正确性证据，不是完整链性能数字。

生产清单仍为 110 个文件，三个资格文件及其文件/清单哈希不变；本切片预计使完整收集从 1120 增加 34 至 1154 项，实际总数与政策 skip 留待最终固定提交完整验收核对。#189 的同机同候选完整链九轮对照、默认配置选择，以及最终正式验收/插件安装/实际宿主交付仍各自保留边界。
