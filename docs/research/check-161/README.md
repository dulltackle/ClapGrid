## 局部性能结果

各组均使用真实公开入口至少三次、相同覆盖与约定的缓存/并发条件；原始样本和局限在各批记录及[后续 UI 测量](measurements.json)中。数字只证明对应组：

| 代表组 | 中位耗时变化 | 结论 |
| --- | ---: | --- |
| 逻辑/服务（#164） | -0.39% | 无实质加速证据 |
| 搜索（#165） | +0.60% | 没有改善 |
| 添加/焦点（#166） | -6.24% | 仅该组下降，候选样本离散约31.997–35.005秒 |

#167/#168 的基线未录逐例 timings，仅能核对禁缓存环境和当时源码；候选实际缓存为 disabled、0 命中。候选报告输出外置，路径与基线不同，OS 页缓存未控制。保留这些差异，不将约1%的波动解释为稳定收益。每轮真实测试、独立 nonce 及进程/context/媒体端口/目录收尾均单列核对。

## 最终验收与成本

正式结论须来自最终固定提交的独立检出：安装锁定依赖，完成类型、环境、全部工具专项、行布局、剩余全量测试、生产构建、源码稳定性及原始结果校验。开发定向结果、局部样本、取消或历史通过都不能替代正式报告。实际 runId、受验 SHA、命令、环境和结果在本轮运行记录以及对应 [GitHub Actions](https://github.com/dulltackle/ClapGrid/actions) 的原始 artifact 核对；本文件不预写成功。

完整 CI 使用实际 job started_at/completed_at、runner 规格、失败/重试及阶段来源。原 #160 的两次真实 job 合计84分58秒，只是相同源码内容下 PR/push 两个样本，不是稳定分位数。新旧环境不对应时，不能相减宣称单次性能收益。分别报告单次执行、删除一次功能分支 push 触发、以及同等提交工作量的总 runner 成本；并发用例时长之和不当作 wall-clock，也不增加 runner 数量制造效率。

源码实现、局部性能、完整验收、插件安装和实际宿主为不同状态。未执行插件更新时，安装包与实际宿主保持原状态；本轮不自动合并 PR、发布或关闭父规格与旧性能事项。main 实际工作流尚无对应执行时保持缺口，不能靠配置阅读代替。
