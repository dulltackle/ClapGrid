# Node 制作归档验收证据

本文件说明制作归档迁移的验收方法和证据范围。执行记录必须另行绑定实际提交、Node 版本与平台；本文件本身不表示检查已通过。

制作入口使用项目声明的 Node 版本及既有媒体工具。日常归档命令和相关测试不要求 Python。固定旧包夹具与离线生成材料保存迁移前的独立基线，离线 Python 对照不构成运行时回退。

## 固定源码与正式检查

先完成定向产品回归、类型检查及独立技术审查，合并前以目标提交的真实 CI 完整结果为主要依据。按 [ADR0011](adr/0011-native-test-frameworks.md)，CI 在自身检出的提交安装锁定依赖，执行类型检查、原生 Vitest/Playwright 全套保留测试及生产构建，保存提交信息、步骤状态和原生报告。

#192 的代码迁移尚待实施；旧 `verify` 独立检出、源码指纹认证与日志协议不再是必须保留的验收要求。本地检查结果限于实际范围，不能替代当前目标的完整 CI；交付源码变化后核对新提交的 CI 结果。旧包夹具验证产品数据兼容，继续保留，与退出的旧测试工具兼容夹具区分。

分别记录最低声明 Node 版本与实际执行版本的结果。平台结论只适用于实际执行的平台；未执行平台、缺失工具和跳过场景明确列为未验证。主题矩阵必须实际启动浏览器。

## 兼容与完整性证据

通过真实统一制作入口读取独立旧包，核对清单、索引与成员原始字节。固定夹具覆盖最低旧 Python 与本机旧实现对照版本；Node 新写包与新读包往返不能成为唯一兼容证据。日常夹具回归不运行其离线生成器。

v1 索引继续保留整数精度、浮点形状、对象顺序和扩展字段。归档核对完整消费 gzip 和 tar，覆盖成员遗漏、额外或重复、摘要与大小变化、有效 PAX 覆盖、损坏文件头和正文、CRC、长度、截断、双结束零块及尾部数据。不支持的成员类型明确失败。

使用真实较大成员分别执行打包和核对，保存进程最大驻留内存与成员大小。比较不同大小成员的资源增长，配合流式实现独立阅读，确认没有按整包大小积存正文；单个小包通过不证明流式资源行为。

## 引用、保护与发布证据

报告保护与必需入包用途分别验证。当前引用遗漏必须失败；历史、待生成及外部指针沿用已有例外。未知扩展和可读但领域格式不合格记录中的原件继续受到报告保护。路径别名、符号链接与已有文件身份须结合实际原字节检查，不能仅断言报告退出非零。

候选包须在目标目录排他创建，完整写入关闭并通过严格自校验后才能替换正式包。分别记录构建、写入、自校验与发布失败，确认旧有效包字节不变，已经生成的候选可定位；候选尚未创建时不能虚报其存在。报告目标预检错误应在归档副作用前失败。发布成功后的报告故障须保留已发布包，并明确发布状态。

在独立空目录恢复旧包与新包，再按独立预期清单核对所有成员原始字节，包括历史审阅及证明原件。恢复后再执行统一核对入口；恢复工具不复用生产校验器作为独立字节预期。

## 无 Python 与交付范围

在 Python 不可用的 PATH 环境中运行真实制作归档入口及相关日常回归，保存不可用证据、命令日志和结果。检查运行链不再启动 Python，同时按原提交逐一核对历史制作与验证档案原字节。

归档成功仅表示内容完整性成立，不提高人工审阅状态，也不认证证明指针真实性。源码与制作工具验收、插件安装包状态、实际宿主验收状态分别报告。本轮迁移不扩大为插件更新或三平台分发；未执行实际宿主验收时，不声称插件已更新可用。
