# 制作交付包

通过统一入口打包与核对，先运行项目媒体检查及对应审阅记录核对，再生成交付包：

```sh
npm run production -- pack --project '/路径/项目' --output delivery.tar.gz
npm run production -- verify-package --project '/路径/项目' --archive delivery.tar.gz
```

需要 Python 3.12 或更新版本的标准库，不使用额外归档依赖。命令缺失、失败和未完成均明确返回非零，详细报告沿用统一入口。归档通过只证明文件完整性，不判定人工确认；`pending`、受控测试、既有确认及对应范围都原样保存，不能因打包成功改成通过。

在 `production.json` 增加非空 `files` 数组，成员来自实际清单，不固定数量：

```json
{
  "files": [
    { "path": "src/动画.tsx", "sha256": "实际文件的64位小写SHA-256", "category": "production" },
    { "path": "evidence/技术检查.json", "sha256": "实际文件的64位小写SHA-256", "category": "technical" },
    { "path": "evidence/用户确认.json", "sha256": "实际文件的64位小写SHA-256", "category": "user" },
    { "path": "evidence/旧版待审.json", "sha256": "实际文件的64位小写SHA-256", "category": "history" }
  ]
}
```

`production` 是制作内容，`technical` 是技术证据，`user` 是人工审阅记录，`history` 是历史原件。分类只描述文件用途，不表示记录内容已验收。文件必须是项目内普通文件，路径为规范相对路径；拒绝重复、越界、符号链接以及未知分类。成员摘要逐个流式计算并与声明核对。清单应包含类型配置、每个口播片段的制作卡、源文件、配音、装配和审阅素材，以及片段显式声明的 `assets`、`lastFrame`、`transitions`、样片视频与采用方案、证据、依赖路径和已有 `video.md`；遗漏时要求补齐清单。声明的证据文件中，当前要求和当前审阅版本记录能定位到项目内实际文件的产物与证明原件，也须列入 `files`；外部网页或聊天指针、尚未生成的待审产物及已失效历史路径不强制存在。该核对只保证原件可恢复，不判断人工结论。其他锁文件、字体、共享源码、参考素材和历史记录也由作者按实际使用列入清单。

清单自身不列入 `files`，避免自引用摘要；工具自动保存清单原始字节，并在 `.clapgrid-package.json` 索引中独立记录清单身份及每个成员的分类、大小、摘要。索引路径保留给工具。不能将交付输出设为清单或制作成员路径。

工具先在目标目录生成候选包，按归档成员顺序读取每个文件、核对全部字节摘要，并将 gzip 流读到末尾核对压缩层完整性。缺失、额外、重复、损坏、非普通成员或清单字节变化均失败；不按无序名字随机反复解压。统一入口在执行前拒绝报告目标为目录、已有非报告文件或不可写路径等可预检错误；只有全部归档校验成功后才原子替换正式包。发布后若出现并发路径变化或不可预测的报告写入故障，报告失败不回滚已发布且校验有效的归档，应按归档身份另行核对。发布失败保留候选位置和原因，已有有效包保持可用，不发布半成品。

恢复时先用原清单执行 `verify-package`，再在空的独立目录按安全归档规则展开。恢复目录中的清单与成员必须再次核对，并通过 `check` 检查实际媒体及配音对应；恢复可播放仍不替代用户听审、视觉判断和完整成片终审。真实宿主素材关联及全片导出另采实际证据，离线包回归不会冒充实际宿主通过。
