# 项目固定归属工作空间

2026-10-03，用户确认首版一个工作空间固定对应一个 ClapGrid 项目，同一工作空间的多个对话共享项目、任务状态和任务锁；对话是访问入口，不是项目身份。关闭并重开 ClapGrid 恢复该项目，不提供项目选择或切换；制作另一条独立视频使用另一个工作空间，以避免新建或分叉对话产生不同制作项目。

该决定替换旧规格中「任务期间禁止切换、结束后恢复切换」的产品前提。MVP.md 与 #33 的相关验收按本轮最终确认同步调整；移除不再适用的要求不代表旧切换测试已经通过。

不同工作空间允许并行制作，分别保存数据、维护任务锁并自动连接正确服务；用户无需选择端口，一个工作空间的任务不锁住另一个工作空间。项目数据统一放在工作空间根目录的 `clapgrid/` 子目录，同一工作空间的所有对话使用同一位置；没有本地工作空间时不启动，提示先选择或创建工作空间，不使用临时目录或连接其他工作空间的项目。

工作空间按实际目录区分：同一目录的路径别名共享项目，同一 Git 仓库的不同检出目录拥有独立项目；在同一目录切换 Git 分支仍使用原项目。

旧位置的项目通过一次性的显式迁入流程兼容：用户指定来源，确认没有运行中的任务后，复制到当前工作空间的 `clapgrid/`，保留原件；目标已有项目时拒绝覆盖，不合并。日常打开只使用固定位置，迁入不构成项目切换入口。

多个对话共享项目内容、任务和锁，但勾选与筛选按各自面板独立维护。「处理选中片段」只采用当前对话面板的勾选；无法确定对应面板时明确拒绝并要求指定片段，不猜测或采用其他对话的勾选。

对话更换工作空间后，旧项目后台任务继续，旧面板退出当前对话的操作状态；再次打开 ClapGrid 时连接新工作空间，当前对话不再向旧项目发出操作。回到原工作空间后仍可查看原任务。若无法可靠识别工作空间变化，要求关闭重开并核对身份，不继续沿用旧连接。

自动连接、工作空间绑定、当前对话勾选与旧项目迁入由 [#41 工作空间绑定规格](https://github.com/dulltackle/ClapGrid/issues/41) 承接；#33 收敛为配音期间禁止导出的验证。规格与事项移除不再适用的项目切换验收，保留历史未验证记录；工作空间隔离及跨对话共享锁进入新事项，不标记为已通过。

用户已最终确认完整方案，并要求发布规格。本记录不表示当前插件与业务 MCP 已实现上述能力；本轮同步规格和事项，不直接进入功能实现。
