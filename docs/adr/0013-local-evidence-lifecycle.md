# 本机验收原件与历史制作副本按任务生命周期清理

2026-10-25，用户在 [#252](https://github.com/dulltackle/ClapGrid/issues/252) 确认不再在本机长期保留一次性验收原件及历史制作副本。GitHub Issue/PR 评论是唯一权威持久记录，记录固定提交、环境、命令、实际结果及未验证项；仅争议结论或不可复现结果附关键原始文件，上传前先脱敏。

本决定取代 [ADR0010](0010-code-check-input-boundary.md) 的“保留本机原件”和“保留 48 份 Markdown 历史说明”安排，以及 [ADR0011](0011-native-test-frameworks.md) 的“历史研究与验收原件保留为记录”表述；同步调整 [ADR0004](0004-node-production-archive.md) 的本机历史工程保留安排。ADR0010 的 code-check 输入边界继续适用：历史目录不作为隐藏执行输入，需要的最小输入先迁入代码资源或测试夹具；测试执行机制仍以 ADR0011 为准。

## 范围与生命周期

一次性截图、命令输出、运行日志、`acceptance.json` 和临时运行目录等验收原件只在任务活跃期保留，存放于本轮运行目录（如 `logs/playwright/<run>`、acceptance 运行目录或 `/tmp`），不再新建 `docs/validation/` 归档。Issue 关闭或 PR 合并且摘要写入后，确认无活跃依赖，再手动删除本轮目录；不按固定天数清理，不编写自动删除脚本或新增自动清理测试。定义、排除范围与手动收尾清单以[检查与验收](../agents/verification.md#验收原件与手动收尾)为准。

`docs/productions/`、`docs/design/` 的历史本机副本也不保留；保留当前项目、交付包、测试夹具与 Git 历史。产品项目内的审阅证据、交付包成员、当前 `clapgrid/` 项目数据、仍在使用的制作项目和设计源文件不在清理范围内。三个历史目录的 `.gitignore` 规则继续作为防误提交安全网，不承诺本机保留。

## 追溯与取舍

仅清理当前工作树与本机文件，不改写 Git 历史，不执行 `filter-repo`、BFG 或强制推送；旧原件仍可从固定提交追溯，历史 clone 体积不会因此缩小。开放事项 #40、#48 的失效路径改用固定提交链接，保留摘要与原有证据边界。新政策只约束今后的本机文件，不删除既有 GitHub 附件，不追溯改写已关闭事项或旧提交。

取舍是放弃本机历史副本的即时可用性，换取明确的任务收尾与更少的本机存储占用；复查依靠 Issue/PR 摘要、必要的脱敏附件和固定 Git 提交。历史结论不能证明新候选已经通过。
