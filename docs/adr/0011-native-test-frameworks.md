# 直接使用 Vitest 和 Playwright，退出自研测试基础设施

2026-10-18，用户在重新讨论 [#192](https://github.com/dulltackle/ClapGrid/issues/192) 后确认整体方案，并授权同步规格和设计文档。#174 已完成外层宿主迁移与有限并发，但自研执行、报告认证、watch 和后台验收仍产生维护与运行成本；本轮直接采用框架原生能力，删除旧机制及其专属测试，不保留兼容层。本记录是已采纳设计，代码迁移和性能验收尚待实施。

## 替代范围

本决定替代 ADR0003 的强制本地独立固定提交验收、ADR0006 的自研工作树锁与强制预检/集中复验编排、ADR0008 的自研 UI 选测与持久后台验收、ADR0009 的自研清单/累计/报告/资格调度/准备缓存，以及 ADR0010 的测试源码身份协议要求。旧 ADR 的历史实现与验收结论保留原义；其中产品审阅、制作材料管理和真实宿主交付边界继续适用。

废弃旧测试命令及参数、报告格式和日志目录约定；同步迁移调用者和文档，不提供适配旧协议的过渡层。自研执行器、Node adapter/TAP reporter、AST 选测、统一 watch、轮次和源码身份、累计账本、失败待办、报告认证、历史结果复用、后台 worker、心跳/重连、资格哈希调度及专用缓存协议均属于退出范围。仅服务这些机制的测试、冻结旧生产者、历史对照和夹具随之删除。历史研究与验收原件保留为记录，不要求其旧工具继续可执行。

## 原生执行与产品保障

- Vitest 承担逻辑、HTTP/SQLite、服务及适合 Node 环境的产品测试，直接采用原生收集、过滤、watch、隔离、mock、清理和报告。
- Playwright 采用原生 browser/context/page fixtures、locator、expect、自动等待与调试附件；迁移字符串脚本、手工 Chrome/CDP 启动和结果轮询。原生框架管理浏览器生命周期，必要的产品夹具接入其 setup/teardown。
- 测试范围由原生配置、目录或命名规则表达，不保留第二份自研执行清单。非导入资源、外部程序和配置变化不能假定被原生相关选测完整识别；本地按需扩大选择，CI 执行保留后的全套。
- 采用框架原生并发与隔离配置，按真实资源约束及测量决定 worker 数；不继续维护原有跨执行者资格和调度协议，也不把历史 1+2 配额当作新架构必须保留的形状。同一 runner、总占用不增加的成本约束继续适用。
- 按独立故障及外部后果保留、合并或删除测试，不要求保留旧数量。删除旧机制不必另造测试重现其已废弃的协议；仍有意义的产品保障须有承接说明。

口播片段编辑、配音、素材、成片、数据完整性、产品格式兼容、必要失败反馈与资源清理继续受测。真实 HTTP/SQLite、浏览器和媒体进程用于必须跨越这些边界的场景；保持零重试、禁止 `.only`、零收集失败，必要 UI 测试实际执行，跳过不冒充通过。产品进程在正常退出、失败和取消后得到必要清理，且不误伤其他工作树；实现优先使用框架能力，只保留与具体产品资源直接相关的 fixture/helper，不另建通用生命周期系统。

现有配音导出进程检查消费旧统一报告，媒体退出测试借用后台验收 helper；实施时迁移这些依赖，继续验证导出互斥及真实进程退出。旧 Python 项目归档读取、插件升级后项目数据保留属于产品兼容测试，不能随旧检查协议夹具一起删除。产品制作 `evidence`/`verify-package` 和插件 `plugin:verify` 不属于本轮废弃的测试报告协议。

## 本地、CI 与结果

本地直接使用两套框架的运行、过滤、watch 或调试入口；完整检查可以简单组合类型检查、原生测试和生产构建。取消跨框架统一开发体验、强制独立本地验收及持久后台任务需求；中断后允许重新运行。

CI 是合并前完整验收的主要依据，直接在自身检出的提交安装锁定依赖并执行类型检查、全套保留测试和生产构建，不再嵌套创建独立检出运行 `verify`。使用 CI 提交信息、步骤状态、原生结果、报告和失败附件，不再维护额外报告认证体系。CI 接线须传播失败，必需报告保存失败不能冒充成功交付；取消和未执行明确可见，本地或历史通过不能冒充当前 CI 通过。

每个 PR 与 main push 继续完整检查，保留手动入口；PR 合并结果和 main 提交的结论分别对应实际检出。必要专项不移到定期或合并后。实际宿主安装、加载和交互仍需其独立交付证据，本轮不变更插件交付协议。

## 完成条件

以包含 PR #191 的基线实施，保留 #174 的历史结论。先固定典型本地修改和完整 PR 检查的优化前样本，再完成原生迁移、机制删除及调用者更新；旧测试机制不要求逐协议等价迁移。

本地与完整 PR 两类反馈均须有超出波动的明显改善。前后在可比条件下各至少三轮，记录源码、工具版本、机器、执行范围变化、缓存和配置、端到端时间、中位数及波动；准备、安装、执行、报告保存与清理按实际入口计入，不把移出计时窗口当收益。代表性本地场景逐项披露，watch 热轮不能代替默认单次反馈；记录总 runner 占用、峰值内存及嵌套进程成本。同一 runner、总占用不增加，不通过增加机器或分片达成目标，不设固定秒数或比例。

开发阶段执行受影响原生检查，最终候选以真实 CI 的全套结果验收并核对产品保障及旧机制退出清单。当前仅同步设计文档和 Issue，不代表这些实现或性能条件已经达成。
