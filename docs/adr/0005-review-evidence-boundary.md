# 审阅版本证据判断与命令报告分离

本轮设计的范围、边界和验证方案已获用户最终整体共识确认；证据模块基础重构、样片消费迁移与依赖影响复核均已实现。样片直接消费业务结果，影响模块传入明确影响后由证据模块独立复核，再转换为原报告。本轮保留现有通过政策，仅修复已批准的身份碰撞误拒绝；发现其他规则矛盾或遗漏时单独决定，不借接口整理隐式改变通过条件。

完整实施规格与验收标准见 [GitHub #130](https://github.com/dulltackle/ClapGrid/issues/130)。

证据模块拥有内容、版本、范围、来源和显式复用的核对规则，并在收到明确的受影响产物集合后判断旧证据是否需要重审；影响模块拥有依赖变化及传播范围的计算，样片模块拥有动态视频、视觉范围与用户确认的用途检查和批量制作许可。三个命令保留各自的检查范围：证据和样片命令不自动增加依赖检查，其他终审要求待审不阻止已经确认的视觉范围取得制作许可；机械对应不替代真实执行、独立阅读或用户决定，沿用 ADR-0003。

内部调用改为消费明确的要求、子项和证据判断结果，由报告转换层生成既有输出；保留现有输入格式、报告字段及含义、检查标识和退出状态。接受维护业务结果到报告转换的成本，以避免调用方继续依赖报告结构，同时避免现有报告消费者迁移；任何必要的行为修正或兼容例外须另行确认并记录。

已确认并实施一项行为修正例外：内部按要求 ID 与子项 ID 分别定位，避免两组合法身份因冒号拼接产生同一报告标识而使样片误拒绝；对外报告仍保留原检查标识，因而不承诺该拼接标识全局唯一。已先用真实入口复现 `(direction:visual, video)` 与 `(direction, visual:video)` 的误拒绝，再验证修复；未增加禁止冒号的输入限制。

应用依赖影响时保留原核对结果，独立产生带受影响原因的复核结果；两者分别说明内容对应情况和指定依赖影响下是否需要重审。复核结果的子项、要求汇总和回写资格必须一致，不能保留“子项需重审、整条仍可回写”的组合；保持现有否决和失败规则，对外报告继续按既有格式转换。接受保留两种结果的成本，以免共享结果被修改后使其他调用方误用不同检查范围下的状态。

## 验证边界

保留现有真实命令回归，并补充标识碰撞的修复前复现与修复后验证、应用依赖影响不修改原核对结果、复核子项与要求汇总和回写资格一致，以及既有报告兼容检查。样片增加批量许可成功分支和其他终审待审仍允许已确认视觉范围的真实命令测试；同时保留受控模式、受控来源各自不能取得许可的反向测试。

成功分支测试仅在隔离临时项目中使用明确标为模拟的记录，组合 `actual-project` 与 `user-confirmation` 字段，验证程序对完整声明的处理；该测试不认证声明的真实性，不作为任何实际项目的用户确认或制作许可，也不新增生产模式的绕过入口。实施回归已经覆盖上述分支；正式验收沿用 `docs/agents/verification.md` 的指定提交独立检出流程，实际提交、日志及未验证范围记录于 [#130](https://github.com/dulltackle/ClapGrid/issues/130) 的运行记录及事项回写。

## 实施结果（#131–#134）

证据模块的 `evaluateEvidence` 直接产出按要求 ID、子项 ID 分别组织的业务结果，保留子项声明、所选证据记录、机械对应结论及可用的原证明信息。报告适配层 `evidenceReport` 从同一份业务判断生成原命令报告，只有该层拼接外部检查标识。v1 输入、状态优先级、来源与最新结论比较、显式复用、整条要求汇总和受控回写限制保持原规则。

`sample` 从 `evaluateEvidence` 的要求及子项获取所选视觉方向的声明与证明，不解析通用报告或拼接检查标识。`impact` 保留依赖传播，向 `recheckEvidence` 传入已解析的产物路径、起因及传播链；证据模块不读取依赖图。复核复制原结果及影响上下文，仅把受影响的已通过子项改为待审，并共享重算要求汇总；已有失败、否决、待审和跳过保持原判断。不同影响集合可独立复核，原核对结果仍说明内容对应情况。

术语表中的审阅证据及证据复用定义已经纳入版本控制，实现细节保留在本 ADR 与接口文档。真实入口回归及前后报告对照使用隔离模拟项目，只提供机制和兼容证据，不构成实际视觉审阅、制作许可或宿主验收。影响命令未提供 evidence 时仍可完成依赖检查，其证据子结果保持待审；证据与样片不自动增加依赖检查。
