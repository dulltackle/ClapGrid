# 制作归档统一到 Node

2026-10-13，用户在完成[迁移可行性评估](../node-archive-migration-assessment.md)后，选定制作归档统一到 Node 的方向，继续推敲迁移方案。现有 Node 制作入口与 Python 归档实现分别解释项目文件引用，增加了运行环境和领域规则的维护成本；统一后由 Node 承担归档与引用解释，项目继续拥有严格的完整性校验规则，不能仅以通用 tar 解析成功代替校验通过。

此前已确认：以保持现有制作入口行为为目标，报告保护与归档必需文件保留各自用途规则；作者继续明确声明交付成员、分类和内容身份，工具核对遗漏，不自动补齐成员。归档完整性继续遵守 ADR-0003，不代替实际执行、独立审查或用户确认。

用户进一步确认，制作命令与相关日常测试均移除 Python 执行依赖，迁移完成后不保留日常命令中的 Python 回退；历史制作档案中的 Python 脚本作为原始复现材料保留。2026-10-17 按 [ADR0010](0010-code-check-input-boundary.md) 改为本机原件与旧提交保留，退出当前 Git 跟踪和代码检查；长期回归的独立旧包夹具继续跟踪。迁移期间可用原实现离线对照，长期回归保存独立生成的旧包夹具。

兼容范围以 ClapGrid 生成且当前校验通过的交付包为准，保留旧索引、中文长路径及 PAX 等实际交付能力；不承诺复刻 Python 读取器接受的全部历史 tar 格式。范围外格式明确拒绝，不能静默跳过。用户明确接受这项读取范围的收窄，以避免为未采用的历史格式承担完整兼容成本；它不豁免旧包索引兼容或严格完整性检查。

采用锁定版本的成熟 tar 依赖处理归档格式，项目负责成员完整性、严格结束规则和可靠发布，接受相应依赖维护成本。相较自行实现完整 tar 编解码，这一选择避免长期维护全部格式细节；通用库自身的解析成功仍不足以证明项目校验通过。

用户确认优先采用锁定版本的 `tar-stream`，搭配 Node 内置 gzip、摘要和文件流，并以旧包兼容测试作为选型验收条件；本轮有限样本通过不能代替完整兼容检查。

项目文件引用 module 统一解释制作卡、素材、审阅版本及证明原件，按用途提供报告保护范围和必需入包范围，隐藏字段遍历、版本筛选与路径解释。归档 module 消费这些结果，拥有成员字节校验、严格流结束检查、候选复验与发布，并在实际读取时重新核对文件状态；不再维护另一份制作字段清单。两个 module 的职责按领域知识和归档操作划分，避免调用方重新组合底层步骤。

用户确认新包继续使用现有 v1 索引格式，旧包验证与新包写出共用兼容规则，本轮不引入 v2。归档 module 内部保留原清单字节、有序且无损的扩展值及旧索引序列化行为，覆盖整数精度、整数与浮点区别、对象键顺序、重复键覆盖位置、字符转义和终止换行等影响索引身份的细节。不能直接以普通 `JSON.parse` / `JSON.stringify` 代替，不能将原始字节校验放宽成语义相等；这些兼容知识不暴露给调用方。

## 实施与验收约束

沿用现有制作命令、参数、清单格式与报告状态语义；范围外 tar 格式的明确拒绝是上述已确认的接受范围调整。报告保护继续覆盖历史引用、未知扩展中的既有路径字段以及可读取但格式不合格的数据；归档必需集合继续按明确用途和当前审阅版本选择，保留待生成原件等既有例外。引用解释不证明后续文件未改变，报告写入和归档读取仍需保留操作时核对。

先固定由原 Python 实现独立生成的 v1 成功包和损坏包夹具，再完成 Node 归档与引用解释集中、替换测试中的 Python 执行调用。长期回归通过真实制作入口和 module 的用途结果检查可观察行为，不仅让新写包器与新读包器互相证明。迁移期间的原实现对照不成为日常运行回退。

验收保留现有归档回归，并覆盖旧索引特殊值、中文长路径与 PAX 的有效覆盖、空文件、较大文件流式处理、成员缺失/额外/重复/摘要变化、文件头与正文损坏、gzip 完整性、双结束零块及尾数据、路径与原件保护、候选复验和发布失败。候选包仍在目标目录生成，完整校验后才替换正式包；失败时保留原有效包及可定位候选，不把报告后续写入失败等同于回滚已发布包。

定向回归与类型检查稳定后，按项目既有流程对固定提交执行正式验收；最低 Node 版本与实际平台的验证结果分别记录，未执行的平台不记为通过。本轮不修改插件分发与实际宿主行为，也不以制作工具检查代替宿主验收。
