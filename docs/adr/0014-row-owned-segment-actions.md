# 口播片段操作全部归入表格行，移除详情抽屉

2026-11-02，用户在 [#259](https://github.com/dulltackle/ClapGrid/issues/259) 的讨论中确认移除口播片段详情，所有交互都放在表格行内完成。这一决定取代 [ADR0002](0002-ui-component-boundary.md) 中"按需从右侧弹出的覆盖式详情"，以及 [#257](https://github.com/dulltackle/ClapGrid/issues/257) 里以详情为前提的规则。原因是详情和行内承担了重复的入口，造成画面说明展开、详情入口和编辑入口互相混淆；行内操作必须在不依赖悬停和右键的环境中也能被发现。

行内按对象归位：文案、画面素材、配音和画面说明各自承载本区的状态和动作，作用于整个口播片段的动作集中到行尾常驻的本行菜单。右键是本行菜单的快捷方式，两者目标范围的规则相同。画面说明改为原位编辑，和文案共用草稿过程。画面素材的更改和解除、配音的重新生成、历史、保留音频、错误说明以及可拖动的试听进度，都由所在区就地提供。片段被删除后，其草稿通过页脚「回到草稿」查看。

口播片段的交互状态只剩勾选范围、编辑目标和键盘焦点，不再有"查看目标"。#257 关于勾选独立、明确编辑入口、单一编辑位置、草稿保存与交接、目标范围和 Esc 分层的规则继续适用。

## Consequences

- 行内承载的动作增多，780 × 579 的场景须通过各区下拉菜单收纳次要动作，不能退回到只靠悬停或右键才能发现。
- 不再支持逐条浏览片段的 ↑↓ 导航，以及在大文本框中同时对照文案和说明的阅读方式。
- 本轮不再按 ADR0002 的流程先出图、再做可点击原型，而是直接按规格在正式面板中实现，再在真实面板里迭代布局；具体布局随迭代确定，不以本记录为准。
