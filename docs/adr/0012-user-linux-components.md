# Linux 组件在用户目录安装，不依赖系统包管理器

日期：2026-10-22

状态：已采纳（实施规格 [#219](https://github.com/dulltackle/ClapGrid/issues/219)）。

## 背景

原入口只在 Ubuntu 24.04 上用 apt 安装 FFmpeg、Fontconfig 和中文字体，缺少非交互 sudo 时需要额外系统认证。这个限制阻止其他发行版与普通用户首次安装，也使 Ubuntu 26.04 开发机跳过安装恢复专项。

## 决策

自动安装支持 glibc x86_64/aarch64 Linux，不按发行版识别。逐个优先复用兼容的系统组件，其次复用用户目录组件，只下载缺失的部分。Node 延续固定版本、URL、SHA-256、临时目录校验与试运行后发布的方式；媒体组件采用固定静态 GPL FFmpeg/ffprobe，字体采用 Noto Sans CJK SC Regular 2.004。

组件放在插件自己的 runtime 目录。启动入口在子进程环境中设置 PATH 和 FONTCONFIG_FILE；字体配置包含系统字体配置及用户组件字体目录，使 fc-list 和 FFmpeg 使用同一组字体。媒体程序调用方式及产品导出设置保持现有接口。

fc-list、curl、tar、xz、sha256sum、flock 与常用基础工具由环境提供，缺少时返回 13；musl、其他架构返回 11。安装失败返回 13 并说明原因及重试方式，check 缺组件返回 10。安装锁、临时目录清理以及安装和启动独立保留，删除需要管理员认证的退出码 12。

BtbN 上游只保留 14 个日构建和两年月末构建，因此把选定的原始包托管在 ClapGrid 固定 Release，和对应依赖源码、构建脚本及许可说明一起长期保存。版本及两架构摘要固定在入口；后续更换来源或升级组件另行处理。

## 权衡

首次缺组件时多下载约一百多 MB，并信任固定第三方构建；获得跨发行版且无需管理员权限的一套安装逻辑，开发验证矩阵更小。静态包仍依赖兼容的 glibc/内核，安装前的试运行会拒绝无法运行的包；本轮真实平台证据独立记录，不宣称已实测所有 glibc 版本或 ARM 机器。

否决逐个适配 apt、dnf、pacman 和 zypper：包名不同、需要管理员权限，Fedora 默认 ffmpeg 还缺 libx264。自动安装基础工具、musl 和其他架构不在范围内。

## 验证边界

沿用 install/check 命令接口的退出码、错误原因、重试提示和组件目录状态测试。失败路径离线执行；真实下载在干净 Debian 和 Fedora 容器一次性验收，记录重复安装、check、启动、独立状态、用户目录字体枚举和中文字幕导出。CI 不新增 job，继续使用已有系统组件执行全套测试。源码、安装包和实际宿主按插件交付规程分别验收。
