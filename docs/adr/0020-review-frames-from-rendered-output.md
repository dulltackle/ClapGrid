# 审片取帧读取已完成的合成产物

日期：2026-11-08

状态：已采纳。实现见 [#313](https://github.com/dulltackle/ClapGrid/issues/313)。

## 背景

`clapgrid_page_frames` 按编排重新渲染单个页面图层，看不到字幕、素材图层与页面合成后的画面，也看不到片段之间的衔接。审片需要一张覆盖全部图层的接触印样，并能跨片段比较构图和节奏。

## 决策

- **新建独立的业务 MCP 工具生成接触印样，取帧来源是已成功的片段合成预览或成片。** 解码用户实际会看到、会导出的视频文件，不再另做一套合成；`clapgrid_page_frames` 保持不变，仍用于单个图层的动作调试。两个工具输入不同（图层局部时间对视频时间），因此不合并。
- **导出任务成功时记录每个片段在成片中的序号、身份、起点和时长。** 接触印样据此标注片段，`clapgrid_export_status` 也提供这份记录。项目在导出后可能已经改动，不按当前项目推算边界；这项功能之前导出的成片只标全片时间。
- **结果属于制作者自检。** 不写入项目记录，不是审阅证据（[ADR0005](0005-review-evidence-boundary.md)），不阻止导出，也不加项目锁。`current` 为 false 的片段合成预览拒绝取帧；成片不判断是否过期，在印样上注明所用导出任务和导出时间。
- **成片的技术检查不在本工具中。** 响度和空帧检查由导出流程负责（[#274](https://github.com/dulltackle/ClapGrid/issues/274)）。

## 否决的方案

- **按编排重新渲染所有图层和字幕的单帧**：不需要先制作预览，但相当于第二套合成器，可能与真实导出不一致，也无法检查片段之间的真实衔接。
- **扩展 `clapgrid_page_frames`**：同一个工具里会出现两套互斥的时间基准和输入参数。
- **放进 `scripts/production.mjs`**：制作命令负责交付阶段的证据和交付包；审片取帧在制作过程中反复调用，需要服务定位产物并判断预览是否为当前版本。
