# 采用自建页面渲染底座

状态：已采纳（[#268](https://github.com/dulltackle/ClapGrid/issues/268)）。

页面以 `index.html`、`DUR`、确定性的 `render(t)` 和 `READY` 为约定，按内容身份保存不可变副本。画面编排引入页面图层，沿用素材图层的空间、层级和区间规则；页面声明的本句素材参与覆盖校验。修改页面须重新导入并提交新编排，已有预览随编排变化自然过期。

产品使用固定版本 Chrome Headless Shell、`playwright-core` 和薄的逐帧渲染器，不引入 Remotion。Remotion 的[许可按组织规模区分](https://www.remotion.dev/docs/license/pricing)，公开插件无法替使用者确定许可资格；其打包步骤、平台 compositor 与额外进程生命周期也增加分发体积和回收控制成本。项目层自行使用 Remotion 制作再导入视频不受此决策影响。

浏览器与逐帧编码在独立 Node 子进程的进程组内启动，经媒体守护进程管理；取消、超时或服务断开时确认组内活进程退出再释放媒体锁。临时回环静态服务只暴露页面快照及已声明素材，配合请求拦截、CSP 和禁用 Service Worker，维持本地文件边界。背景 JPEG、透明叠加 PNG 经管道编码成 FFV1 中间视频，交给既有滤镜链；字幕继续统一用 ASS 烧录。软件渲染与固定浏览器限制环境差异，页面作者仍须保证每次 `render(t)` 独立且确定。

Linux 组件沿用 ADR0012 的固定 URL、版本、SHA-256 和临时目录试运行后发布流程。浏览器仍依赖系统共享库，缺少时明确安装失败并保留已有组件；源码、安装包和实际宿主独立验收。实时页面编辑、页面音频、GPU/3D 一致性和非 Linux 交付不在此阶段范围内。
