# 测试执行者试点与同次累计证据

2026-10-16，用户在 [#148](https://github.com/dulltackle/ClapGrid/issues/148) 确认以下设计。沿用 ADR 0003 的固定提交证据边界、ADR 0006 的强制预检与集中失败复验，以及 ADR 0008 的真实浏览器和后台任务生命周期保障。本记录确认设计采纳；实现完成、性能达标、固定提交正式验收、本机安装和实际宿主交付分别需要实际证据。

## 决定

首轮仅迁移已确认的 16 项逻辑、4 项真实 HTTP/SQLite 集成和 14 项 UI 固定核心场景；其中 UI 的样式碰撞有 2 项，真实浏览器有 12 项。候选直接开发依赖固定为 Vitest 5.0.5 与 Playwright Test 1.64.1，并提交锁文件。Vitest 使用 Node 环境，Playwright Test 保持原生键鼠、真实 AG Grid 与生产同源 CSS；生命周期、取消、验收任务及未迁移测试继续使用 Node 原生测试器。清单明确唯一执行者、预检及完整范围；单独保留原生对照实现与逐场景映射，不在常规完整检查重复调度。

新增日常入口默认单次执行，显示选择范围、依据、未覆盖项；watch 仅显式开启。静态导入关系只是选择依据之一；字符串浏览器脚本、文件读取、子进程、CSS、配置、helper 与打包输入使用显式映射，无法可靠判断时扩大范围。零收集不能视为通过，局部通过不能升级成完整验收。

保留预检先执行及失败阻塞。同一运行中，实际通过、源码/配置/环境身份一致的预检文件和类型检查可计入完整覆盖，后续仅执行剩余集合；聚合记录必须引用原证据，不伪装成再次执行。不同运行及历史成功不能自动累计。每个执行者保存可读日志与原生报告，统一记录预期/实际文件及用例、逐项状态、失败位置、起止时间、执行者版本及来源。缺报告、收集失败、未捕获错误、取消、身份/集合不符和不完整执行均失败；UI 缺浏览器、跳过或 todo 仍不能通过，其他范围沿用既有政策。正式验收与显式历史复用使用相同校验。

浏览器进程可按 worker 复用，每例独立 context、页面、临时目录及所需后端/SQLite/端口；业务替身保持既有 HTTP 客户端边界。分别测量并发 1 与 2 后再选择默认值；共享资源及生命周期专项保持串行，不通过取消隔离或自动重试掩盖失败。允许复用输入可验证的编译产物，输入含源码、锁定依赖、配置、资源、构建选项与工具版本；未知或损坏缓存重新构建，命中后仍实际测试。

新执行者、worker、浏览器与 watch 均纳入现有工作树锁及登记范围；显式取消由实际拥有者完成，全部本次进程退出后才释放锁。保留同身份正式验收连接、观察者退出不中止任务、异常退出保守处理及其他工作树不受影响。固定提交验收继续独立检出、`npm ci`、完整类型检查/测试/生产构建及源码变化检查。

## 验证与推广边界

以真实命令、隔离小仓库、真实子进程和报告故障注入验证上述约定。保留业务输入输出、真实 HTTP/SQLite 和真实浏览器外部行为断言。原生/候选在同机、固定试点源码、相同行为覆盖下各至少执行三次，记录冷/热缓存、并发、环境、准备/交互/清理及端到端时间，取中位数：逻辑 ≤1.5 秒，HTTP/SQLite ≤2.5 秒，UI 固定核心完整入口（含类型、测试、构建及清理）≤35 秒。UI 对照采用既有并发 2；并行场景累计时间不能当作 wall-clock 占比，长期 watch 重跑不能替代单次预算。

先交付报告与执行清单，再逐组迁移、累计覆盖/生命周期回归、性能对照及固定提交完整验收。预算不达标时保留原有通过路径、定位和优化，不扩大迁移。当前不承诺全套加速比例，也不一次性迁移全部测试、不新增模拟 DOM 体系、不改变产品业务、不自动安装/更新插件或合并/发布。

## 取舍

引入两个执行者及适配层增加维护成本，换取逻辑反馈、浏览器准备复用和定向检查能力；显式清单与逐项证据防止迁移漏跑。设计采纳不保证这些收益已经实现。运行命令、证据格式与当前阶段见 [检查与正式验收](../agents/verification.md)。

### 启动与准备成本的优化边界（#156）

用版本化完整内容身份和短期线程分摊当前读取，保留全部代码检查输入；2026-10-17 按 [ADR0010](0010-code-check-input-boundary.md) 排除独立制作工程和历史产物，原“全部原输入”不再包含这些历史目录。默认 4、API 上限 8 的选择兼顾线程启动、CPU/内存及磁盘竞争。纯 Vitest 框架准备可与读取重叠，项目代码仍在本次身份完成后执行；历史目标保留旧协议和身份形状。

只对已确认隔离的 segment、table、wide 文件内并行，speech/CSS 保持串行；CSS 共用 worker pool 而不创建浏览器。每例隔离、真实键鼠、原脚本/等待/断言和零重试保持原决定。开发 JS 压缩保留名称、CSS 工具延迟到 miss 真实编译，减少准备成本；缓存仍按完整当前输入核对。

读取复用限于同一连续同步、封闭只读边界，准确前缀状态继续消费原连续 SHA 字节流，不跨 await/view 使用历史字节。未采用通用历史投影 LRU 或已载工具快照：当前工具集合的复制/驻留成本及与前缀复用的抵消作用，不足以用组件差值证明完整 helper 收益。

Node 字节码自动默认限于单次受控测试 child，watch 派生链关闭该默认，显式控件保留；正式独立检出按实际目标派生。缓存命中始终只是编译准备复用，真实执行、同次累计及历史成功复用各自保留原证据条件。

取消先通过实际组归属与完整拥有者绑定确认的控制通道请求合作收尾，再沿原进程组边界兜底；轮末资源清理前确认全部本次登记组已退出。未知/变化的拥有权保留现场，清理期间仍处理取消信号。该协议不根据目录名或不可见 PID 推断其他任务已结束。

这些选择增加身份协议和实现审查成本，需以真实进程、helper、报告及故障反例验证。原覆盖与预算不变，样本或组件下降不等于完整入口达标；性能方法、协议与交付边界见 [试点记录](../research/test-executor-pilot.md)。

### PR 全量检查优化的后续决定

2026-10-17，用户针对 PR #160 的实际检查耗时确认：每个 PR 继续执行全量测试，不将检查工具、watch、生命周期或验收系统自身的专项后移到合并后。自动检查只保留 `pull_request` 和 `main` 分支的 `push`，保留手动入口；功能分支不再因 `push` 额外执行一套检查，尚未创建 PR 的功能分支不取得自动检查证据。PR 仍验证合并结果，main push 验证 main 提交，不跨事件自动复用通过记录。

后续优化重点是充分利用 Vitest 和 Playwright，允许按实际热点逐组扩大迁移，替代本记录首轮“性能预算未达标不扩大迁移”的推广限制。每个场景的行为覆盖、真实浏览器执行、隔离、零重试、取消清理和原始证据要求继续保留；扩大迁移不意味着所有真实进程专项必须更换执行者。优先缩短等待完整检查结果的时间，同时约束总 runner 成本。本轮不预设耗时目标，以实际优化前后测量判断收益；既有试点的历史性能缺口不因此改记为达标。

用户进一步确认允许精简甚至移除自研测试执行层，充分使用 Vitest 和 Playwright 原生的收集、调度、隔离、浏览器复用及报告能力；必须保留全量行为覆盖和必要验证保障。现有执行层结构不再是必须保留的约束，删除或替换前须证明完整性核对、失败反馈、固定提交来源及取消清理仍可靠。项目特有且框架不能直接提供的保障可保留最小适配，不以原生退出码代替完整验收。

本段记录已确认的设计方向，不表示工作流或测试迁移已经实现。实施规格见 [#161](https://github.com/dulltackle/ClapGrid/issues/161)；实现、性能测量和固定提交完整验收分别提供证据。

## 全量原生调度收口（#171）

常规清单110文件由38 Playwright、18 Vitest和54 Node唯一承接，预检范围不变，历史对照仅comparison-only。Playwright沿原文件级模式使用原生worker池，每例仍隔离context/page/目录与资源端口；普通test-runner默认请求2，显式--concurrency 1保留。UI快检/相关入口继续执行计划器的maxConcurrency，不将非静态或未知范围自动提升为并发2；Node生命周期/共享环境专项与Vitest服务保持原有串行/isolate边界。没有增加机器或分片。

废弃checkBrowser的dumpDOM启动/独立构建路径已无调用者并删除；Chrome发现及四个历史原生对照使用的interactive-browser保留。已删除的重复报告、MemoryBuildCache和内部冗余对照与替代保障见[最终职责/完整范围/测量材料](../research/native-scheduling-171/README.md)。自研只保留唯一归属、严格UI、源码/环境身份、原始报告完整性、同次累计与复验、工作树锁与拥有者取消清理、可核对输入的准备缓存；原生框架负责收集、调度、worker池与原始逐例生命周期。

调度选择以同候选同覆盖真实资源隔离的三次代表测量为依据；Vitest threads/forks与单/双project同样保留实际原件，不把子集wall-clock或运行器选择当作全量CI收益。性能数字不替代最终固定候选的独立完整验收。缓存命中仍实际执行，历史passed不自动累计，retry仍为0，缺浏览器/零收集/严格UI skip或todo/取消/报告缺损与错身份仍失败。

## Node 文件级有限并发的首轮范围

2026-10-18，用户在执行隔离与有限并发的设计讨论中确认：首轮只在同一 runner 内，对已经验证资源隔离性的 Node 文件启用最多两份文件级并发；共享资源专项继续串行。Node、Playwright、Vitest 之间的重叠执行及多 runner 分片留待后续讨论，以便单独确认隔离可靠性并测量本轮收益。

全量覆盖、零重试、预检顺序、原始证据与取消清理要求继续沿用。此决定仅确认设计范围；具体文件分组、隔离实现与性能采纳条件仍在讨论，不表示已修改执行器或取得并发验收证据。

### 后续调整：统一 Vitest 宿主，分两步验收

同日，用户进一步确认目标方案调整为：常规 Node 测试的外层宿主统一到 Vitest，允许在强制预检之后让 Vitest 与 Playwright 有限并发；先完成等价迁移验收，再启用跨执行者并发并单独验证性能和稳定性。此调整替代上段将优化限于 Node 文件级并发、暂不重叠执行者的首轮范围；同一 runner、完整覆盖、预检顺序、零重试、来源核对及取消清理约束继续沿用。

被测行为需要的真实 Node 子进程、原生测试器及历史夹具可以保留；外层宿主统一不表示将这些验证对象替换为 Vitest，也不表示所有测试都取得并行资格。迁移后的 pool、worker 配额与性能采纳条件尚待确定。本记录仅确认设计，不代表已完成迁移或并发验收。

用户随后确认第一步采用统一 Vitest `forks` 基线、单 worker 且文件串行，现有18个 Vitest 文件也纳入基线验证；Playwright 执行方式暂时保留，执行者之间仍串行，以单独验证54个 Node 文件迁移后的行为、逐例清理、mock、超时、失败反馈和来源完整性。第二步在同一 runner 上先验证 Vitest 1 worker + Playwright 1 worker，再与 Vitest 1 + Playwright 2 对照，以完整检查耗时、总 runner 占用、峰值内存和稳定性确定配额；测量包含工具测试实际启动的嵌套 Chrome、FFmpeg 和后代进程，不把框架 worker 数当作全部资源上限。并发资格和性能采纳条件仍待确定。

用户进一步确认迁移通过与并发资格分开：强制预检先执行，预检后的文件只有在确认资源隔离并通过重叠验证后才进入并发段；未知或需要独占资源的文件进入独占段，不与另一执行者重叠。资格集中记录，文件收集和调度继续使用原生框架，不通过统一宿主自动赋予并发资格。

性能采纳比较同机、同提交、同覆盖的串行基线与并发候选，每种至少三轮；完整链耗时中位数下降、总 runner 占用不增加、覆盖和清理全部通过才采用并发，峰值内存用于评估资源余量。没有实测收益时，保留已通过等价验收的宿主迁移并采用串行配置，不用子集改善代替完整检查收益。用户随后调用 to-spec 将讨论综合发布为 [#174](https://github.com/dulltackle/ClapGrid/issues/174)，标记为 ready-for-agent；本轮仅记录设计并发布规格，尚未执行代码迁移。

### 重新审视测试成本与保留标准

2026-10-18，用户重新讨论提速方案及既有约束，确认本地开发反馈与 PR 检查等待同等重要，暂不设硬性时间预算，要求实际明显提速。重新审视后，用户选择先执行既定迁移与并发，再精简测试。

用户确认以独立故障保障判断测试价值：保留关键用户行为、数据完整性和必要的失败及清理保障；允许合并或删除重复覆盖同一故障、只约束内部实现、或验证已不需要机制的测试。每项删减须说明失去的保障及其承接方式，不要求保留现有测试数量。这调整了前述保留全部既有行为覆盖的设计约束，但不允许仅因耗时长而删除唯一的必要保障。

每个 PR 继续运行精简后保留的全套测试，本地按改动执行相关检查；本轮不将慢专项后移到定期检查。实施顺序沿用前述统一 Vitest 宿主的等价迁移、通过隔离验证后的有限并发，再依据独立故障保障精简测试。迁移与并发阶段保留原覆盖，测试删减作为后续独立阶段，以便分别核对行为等价、并发收益和删减取舍。

用户进一步确认：本地开发反馈与 PR 检查两类都改善才算完成，单独缩短其中一类不能满足本轮目标。以固定的典型本地改动场景及完整 PR 检查链分别比较，优化前后在可比环境下各至少测量三轮，记录端到端中位数与波动，包含准备及清理；收益应超出运行波动，不设固定秒数或改善百分比。迁移、并发、精简分别记录结果，某类尚无改善时继续定位，不以另一类或局部子集的收益代替。

用户已确认整体方案并调用 to-spec，后续规格发布为 [#192](https://github.com/dulltackle/ClapGrid/issues/192)，标记为 ready-for-agent。具体删减清单须在实施时依据独立故障保障审视；本次讨论与发布没有改变执行配置或删除测试，不能据此声称提速或验收通过。

发布时核对到 #174 已关闭，迁移与有限并发已通过 PR #191 合并到 main，合并提交为 `62c19c3f890d76889a0ff48a33087d0f7cfe2bc8`。因此 #192 承接已完成前置，实施剩余的测试精简及本地/PR 双场景提速，不重复迁移或改写 #174 的验收。历史同机候选的完整链中位数由 1747.581 秒降至 1732.681 秒（约 0.85%），不代表本轮两类反馈均已明显改善，也不是最终合并源码的新测量。原讨论工作树仍是较早分支；上文“尚未迁移”等表述保留原讨论阶段含义，当前实现以已合并成果为准。

## 两步迁移的第一步串行基线（#174、#186）

本阶段将余下 54 个常规 Node 文件迁入 Vitest；清单仍为 110 文件，当前唯一归属是 72 Vitest 与 38 Playwright。旧 18 个 Vitest 文件与新增迁移统一为 forks、一个 worker、文件串行、isolate、retry 0；执行者之间继续串行，Playwright 保持既有执行方式和默认请求 2。此段更新上文 #171 的历史清单与 threads 选择，不改变历史测量结论。

先证明完整行为等价，再进入执行者重叠与资源配额阶段。第一步等价不以加速为条件，本节记录的当时第二步尚未实施或验收。54 文件 817 原场景、旧 Vitest 86 项、Playwright 196 项及 14 个独立新增回归分别可追溯；普通非 UI 平台能力 skip 保留原理由，严格 UI 仍要求逐例实际通过。映射、真实调用者和证据边界见[阶段审计](../research/native-migration-186/README.md)。本提交确立串行配置与阶段边界；等价结论以对应固定提交的独立检出、锁定安装及完整 verify 原件和事项证据为准。

Node adapter、TAP reporter、历史快照与冻结旧生产者仍有真实调用者，按调用与保障审计保留。原生框架负责常规收集、调度和逐例生命周期；项目特有的 code-check-v1 身份、完整原始来源、唯一归属、预检顺序、同次累计、失败复验、严格 UI、工作树锁与拥有者取消清理继续成立。迁移保留原时限、真实 Node 子进程和逐例资源/mock/环境恢复；本阶段不增加新的模拟宿主、分片或 runner。

### 取得资格文件的显式重叠对照（#187）

在第一步串行等价验收后，第二步采用与唯一执行归属分开的集中资格 allowlist。未知/新增默认不取得资格；缺失归属拒绝，已登记文件或清单内容变化不能继承旧资格。完整强制预检及同次累计先完成；剩余独占集合先运行，再用原生入口重叠取得资格的 Vitest 单 forks worker 与 Playwright 1/2 worker。直接测试、预检和集中复验继续串行。这里只增加三段薄编排与身份/证据绑定，原生框架继续负责文件收集、调度和逐例生命周期。

两路报告与日志独立，子 nonce 由随机父 nonce 固定派生并在汇总时重新核对；原始来源、完整并集、严格 UI、源码/环境、集中复验与拥有者取消边界不变。普通失败仍收齐另一侧，全部本次登记后代及资源退出后才解锁。首组实际原文件的隔离依据、逐例重叠与取消原件见[本切片记录](../research/native-overlap-187/README.md)。

#187 当时默认仍为 `serial`。显式 `--execution serial|overlap-1+1|overlap-1+2` 提供同提交完整入口对照；#189 采用条件是各至少三轮、完整链 wall-clock 中位数下降、总 runner 占用不增加且覆盖与清理全部通过。无候选满足则保留串行，不设置额外百分比或内存门槛。局部资格通过不等于 #188 故障边界、#189 性能选择、最终固定提交正式验收或宿主交付完成。

### 取消后的迟到后代归属（#188）

真实重叠反例证明：把已取消祖先从登记链移除，并仅消费一次组快照，会在本次迟到后代仍运行时释放根锁。取消状态仅阻止新业务/独立检查进入，不能解除已经开始的拥有者的后代归属；完整绑定未被替换的同 token 祖先仍接收迟到登记。

统一 drain、finally 与异常恢复持续重扫登记，资源清理及控制通道关闭后再次核对全部组/资源；每个异步边界核对完整 root/token/pid/birth/namespace。未知或替换的绑定保留现场，不以新 PID 追认或删除登记绕过确认。两种配额的真实 Chrome/FFmpeg/子测试、迟到登记和独立 worktree 反例及故障后实际集中复验见[本切片记录](../research/native-overlap-188/README.md)。三个原文件资格不扩大；#188 当时默认串行，#189 的后续采纳与最终固定提交验收分别进行。

### 完整链测量后的默认选择（#189）

同一机器、同一固定候选 `f049da10cd1743288751fa190283a8dce80b3e90`、同一安装及完整覆盖，按 Latin9 顺序对三种模式各执行三轮；全部九轮覆盖、原始来源与清理均经独立审阅。采用 `overlap-1+2`：完整链 wall 中位数从 1747.580739308 秒降至 1732.68068146 秒（约 0.85%），三轮总 runner 占用从 5241.653407041 秒降至 5199.022461433 秒。`overlap-1+1` 两项均高于 serial，不采用。无额外加速百分比或内存阈值。

收益幅度较小，且 1+2 的内核计费内存峰值、RSS 观测峰值与 cgroup CPU 使用更高，详见[完整数据、方法和限制](../research/native-overlap-189/README.md)。每轮仅清空五类私有缓存，未清 OS 页cache；此本机结果不承诺托管 CI 固定耗时。原无效轮全部保留且不计入九轮。

当前 `npm run check` 默认选择 1+2，显式 `--execution serial` 保留。强制预检、独占先行、三个原文件资格及哈希失效策略、Vitest 单 worker/文件串行、Playwright 请求 2、零重试、原始证据及拥有者 drain 不变；未知或失效资格仍独占。测量提交的默认仍是 serial，九轮使用显式模式；本默认变更是后续源码候选，最终提交/源码身份另行固定，交 #190 作默认完整正式验收与适用 CI。该决策不证明安装包或实际插件宿主已更新。
