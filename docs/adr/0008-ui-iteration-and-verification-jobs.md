# UI 快检与可查询的验收任务

2026-10-16，用户确认本次复盘的 1–5 项实施边界：缩短 UI 反馈、固定已有关键检查、避免验收重复执行、减少浏览器重复准备，并改进面板更新流程。本记录确认设计，执行结果由对应检查和交付记录提供。

沿用 ADR 0003 的证据边界：新增 UI 开发检查，明确记录范围、源码身份和未覆盖项；完整正式验收仍在独立固定提交中安装锁定依赖。CI 和正式发布保留完整检查，本次检查工具及交付机制自身的改动在稳定后统一正式验收。

UI 快检使用维护在代码中的固定核心清单，至少包含样式碰撞、表格控件点击范围、双层行与说明展开、配音状态、宽面板布局；按改动追加编辑、菜单、选择和主题专项。浏览器缺失直接失败。初版先记录准备与交互耗时，在同次运行内按完整输入身份复用 JS/CSS 构建；各场景保持独立浏览器数据与临时目录，有限并发经对照测量后启用，不直接提高整个测试集的并发。

正式验收任务与终端观察连接分离，提供稳定 runId、状态、阶段、心跳、日志和失败摘要。相同仓库、固定提交、源码指纹、检查配置及工具环境的活跃任务只执行一次；终端断开后先查询任务。状态和任务注册原子发布，失去心跳不能直接判定停止，确认原任务已结束后才允许重试。成功记录复用保留原时间、身份和原始证据，不冒充新执行。

## 已确认边界

- 纯样式与布局调整走 UI 本地检查；事件、保存、编辑、请求、协议或依赖变更升级检查范围。修改位于前端目录本身不代表纯 UI。
- 活跃任务默认去重；历史成功记录仅在显式选择时复用。

2026-10-16，用户确认将表格主题的纯颜色值替换纳入静态样式识别，具体识别边界见 [检查与正式验收](../agents/verification.md)。采用明确颜色字段白名单，避免任意主题配置都被视为纯外观；保留现有全部面板浏览器测试，先消除颜色调整触发全项目检查的额外要求，不同时收窄主题测试覆盖。CI 和发布前的固定提交完整验收沿用既有规则。

2026-10-16，用户选择方案 A 统一整合 PR #146 与已合并 #145。本记录细化 ADR 0006 的重复启动规则：同身份正式验收连接原任务，只增加观察者；同工作树的其他检查仍互斥，不同工作树独立。后台 worker 预约并接管同一生命周期锁，保留 ADR 0006 的控制通道取消、全部登记进程组清理、强制预检和集中失败复验。观察者退出不取消执行；显式取消由实际拥有者确认完成。中断判定依据登记进程组，不再只扫描 worker 原 session；历史成功复用同时验证预检与结构化报告。

## 首轮测量

同一组 14 项 UI 核心用例在本机串行耗时 60.46 秒，限制并发为 2 时耗时 32.31 秒，均为 14 项实际通过、无跳过或取消，逐例 JS／CSS 构建身份一致。交互约占串行耗时 50.45 秒；构建缓存消除了重复准备，但并发只对已确认隔离的文件启用。此记录是开发反馈性能对照，不代替固定提交的正式验收，也不承诺其他机器的耗时。
