# 风格制作与引用

风格是可跨项目复用、可执行的视觉语言；项目的视觉方案记录实际采用的规则。内置风格位于[插件 styles 目录](../plugins/clapgrid/styles/README.md)，构建会完整打包该目录。示例视频放在文档或 Release 中链接，不进入插件包。

## 目录约定

每个风格目录包含 `STYLE.md`、`lib/` 和 `example/index.html`、`example/page.json`。`STYLE.md` 使用以下头部；项目复制后追加来源，保留项目版本自己的 id 与 version：

```yaml
---
id: project-style
version: "1"
source:
  id: builtin-id
  version: "1"
---
```

说明固定包含：本质与“它不是什么”、材质与渲染、配色逻辑、字体（含字幕推荐字体与字号）、运动质感、镜头语法、转场、修改分级（放心改 / 一改就变味 / 不能改）。不含声音栏。风格不绘制字幕；按推荐设置项目统一导出字体与字号。

`lib/` 是 ES module，只导出依赖 `t` 与传入参数的纯函数；每次绘制独立确定。纸纹、描边、镜头、缓动与转场都遵守这一约定。`example/` 遵守[页面约定](../README.md#画面素材与编排)。为避免内容摘要自引用，源示例的 `page.json` 与模块路径用 `STYLE_ID` 占位；风格导入后，将示例复制到风格目录外的页面目录，把占位替换为返回的 styleId，再导入页面。示例 DUR 同步实际图层区间；图片、字体和模块在 READY 前就绪。

## 选用和修改

1. 阅读 `STYLE.md`，将选中的内置风格整个复制到工作空间 `styles/<id>/`，追加来源。插件更新保持此独立副本。
2. 在 `video.md` 的“风格”小节链接该目录的 `STYLE.md`，先写本项目方案，再阅读示例源码。按修改分级调整项目风格。
3. 用 `clapgrid_import_style({ sourceDirectory })` 导入工作空间内绝对目录，得到 styleId；不可变副本存于固定项目的 `clapgrid/styles/<SHA-256>/`。同一内容重复导入返回相同身份；修改工作副本后重新导入，不编辑已导入副本。
4. 页面可含严格的 `page.json`：`{ "style": "<styleId>" }`，页面导入时核对风格存在与完整性。模块使用绝对路径，例如 `import { draw } from '/styles/<styleId>/lib/draw.js'`；临时服务只开放该页声明的风格。未声明、其他风格或越界路径返回 404，并使任务失败、指明片段。没有 page.json 的页面继续使用原页面约定。
5. 风格变化后重新导入，更新页面声明和模块路径、重新导入页面并保存编排。旧预览随编排变化显示待更新；更新采用方案中的风格身份，重新展示动态样片并取得受影响范围确认。样式稿保持可选。
6. 交付前与示例比较六个维度：题材与对象、构图、配色、材质、运动与镜头、转场。至少四项不同；在项目方案记录差异。这是制作者自检，工具不机械核对，也不作为审阅证据必需项。

## 导入边界

页面与风格共用白名单 html/js/mjs/css/json/svg/png/jpg/jpeg/webp/woff2/ttf/otf/md，最多 256 个文件、32 MiB（含说明与示例）。按相对路径及实际字节计算 SHA-256；拒绝符号链接、多硬链接、特殊文件、目录外引用和工作空间外路径。已存在副本只核对，不覆盖；使用前再次核对完整内容身份，篡改副本被拒绝。纯函数、说明栏目和美术效果由作者自检与观看确认。

HTTP 入口为 `POST /api/codex/import-style` 与 `POST /api/style/import`，请求为 `{ "sourceDirectory": "工作空间内绝对路径" }`，返回 `style: { styleId, fileCount, bytes }` 和项目状态，遵循现有修改权流程。采用方案与样片确认格式见[样片接入说明](production-sample.md)。
