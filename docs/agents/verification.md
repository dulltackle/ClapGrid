# 检查与验收

当前采纳设计是 [ADR0011：直接使用 Vitest 和 Playwright](../adr/0011-native-test-frameworks.md)，实施规格为 [#192](https://github.com/dulltackle/ClapGrid/issues/192)。2026-10-20 已迁移产品测试与 CI 接线，并删除旧机制。稳定候选的完整测试、构建和真实 CI 结果以本轮实际执行记录为准，尚未执行不能算通过。

## 开发检查

直接使用 Vitest 运行逻辑与服务测试、过滤或 watch；使用 Playwright 运行和调试浏览器测试。按变更执行定向测试及必要类型检查、构建；非导入资源、外部程序或配置变化需显式扩大范围，不能假定原生相关选测覆盖所有依赖。样式和 UI 变更同时实际核对面板。

`npm test` 为 `vitest run`，`npm run test:ui` 为 `playwright test`；定向、watch、调试直接传入各框架原生 CLI。`npm run check` 仅依次组合 `typecheck`、两套原生测试与 `build`，无后台状态或旧命令转发。完整退出清单见 [native-retirement](../testing/native-retirement.md)。

本地检查允许未提交内容，结论限于实际运行范围。完整检查可以简单组合原生命令；取消强制本地独立检出验收、统一跨框架 watch、持久后台任务及历史失败待办。普通前台命令中断后允许重跑，取消和未执行不能算通过。

## 测试迁移与删除

原生框架负责收集、调度、隔离、浏览器生命周期、等待、清理和报告。旧执行器、AST 选测、清单、身份与累计、报告认证、后台任务、资格调度和专用缓存协议连同专属测试退出；旧命令、格式和日志目录不保留兼容层。产品 fixture/helper 接入原生生命周期，不另建通用执行或认证系统。

按独立故障保留、合并或删除测试，记录仍有意义的产品保障如何承接。口播片段编辑、配音、素材、成片、数据完整性、产品兼容及必要资源清理继续受测；旧测试协议夹具与旧产品归档夹具分开判断。必要边界实际运行 HTTP/SQLite、浏览器和媒体进程；配置保持零重试、禁止 `.only`、零收集失败，必要 UI 不用跳过代替通过。资源清理只作用于本次拥有的产品资源。

## CI 完整验收

CI 直接在自身检出的提交上安装锁定依赖，执行类型检查、精简后保留的全套测试和生产构建；不再嵌套运行独立 `verify`。以 CI 提交、步骤状态、原生报告及失败附件为依据；失败须传播，必需报告的保存失败须可见，不增加自研报告认证。

每个 PR 全量执行主检查与 Linux 导出进程追踪，保留手动入口；main push 不再自动重复执行。main 必须通过 PR 合并，GitHub 分支保护要求 `check` 与 `process-trace` 均由 GitHub Actions 提供并通过，启用严格的“合并前分支必须与最新 main 同步”，管理员同样受约束，禁止强制推送和删除 main。main 前进后，其他 PR 须更新分支并重新检查。此保护是取消 main 自动检查的前提；保护未生效时不得采用该流程。

PR 合并结果和手动 ref 的结论分别对应实际检出，不跨运行复用成功结论，也不把 PR 通过表述成 main 提交重新测试通过。保留现有自动事件去重策略，手动和重跑独立；必要专项仍在合并前执行。发布安装包时针对实际发布产物独立验证。真实 CI 未运行时明确待验，本地通过不能替代。插件安装包及实际宿主状态仍按 [插件交付](plugin-delivery.md) 分别验证。

## 性能与历史参考

2026-10-20 用户确认本次本地代表场景与完整 PR 链改前、改后各 1 轮，明确取代原三轮及改善超出波动的要求。只报告实际变化，计入准备、安装、执行、报告保存和清理，披露范围、工具、环境、缓存与配置差异、runner 总占用、峰值内存及嵌套进程成本；同一 runner、总占用不增加，不增加机器或分片，不设固定秒数或百分比。单轮不推断中位数、波动或稳定改善；定向开发迭代不是额外性能样本。详细完成条件见 ADR0011。

[旧验证协议](verification-protocols.md) 仅供定位尚未删除的实现、收尾已经启动的旧任务及理解历史证据，不是 #192 的兼容或验收要求。历史研究及通过记录保持原义，不能作为新候选的执行结果。
