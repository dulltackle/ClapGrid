# 检查与正式验收

`npm run check` 检查当前开发目录，允许未提交内容。日志位于 `logs/check/`，记录提交、源码树、跟踪文件与未忽略新文件的内容指纹、检查阶段和结果。发现阶段间源码变化时返回非零并标为 `invalidated`；起止一致不能证明运行期间从未修改。

## UI 迭代

纯静态样式和布局调整先执行 `npm run check:ui`，再打开实际面板核对。默认扩展集包含点击范围、表格控件、双层行、说明展开、配音状态、宽窄屏、长文案和悬浮；固定核心不会省略已有的 24px 点击范围检查。组件到追加测试的映射由 `scripts/ui-check-plan.mjs` 维护，避免临时猜测。

- `npm run check:ui -- --plan --base <提交>` 只查看范围及升级原因。
- `npm run check:ui -- --base <提交>` 运行类型、真实浏览器用例及构建，日志位于 `logs/check-ui/`。
- `--scope row` 选择固定核心；`--concurrency 1|2` 仅对已确认隔离的 UI 文件启用有限并发，安全范围默认 2，扩展到其他用例时保守回到 1，不改变全套测试并发。输出记录实际采用的范围和并发。

默认 `--base HEAD` 比较工作区；检查已提交的修改时应明确选择修改前的提交。静态 className 字面量和未改变导入／扫描规则的 CSS 可判为样式变化，无法证明为静态的配置、事件、保存、编辑、请求、协议、依赖及检查工具变化均保守升级；不能仅因路径位于前端目录就判为纯 UI。列宽等 TSX 配置变化在首版也可能升级，由范围报告说明。

UI 结果明确标记 `ui-development`，只证明其测试范围。退出 0 且 `completeForLocalUi:true` 才通过本机 UI 快检；含非样式变化时，即使用例通过也返回退出 2、`requires-full-check`，等待完整检查。`--scope row` 不能绕过这个边界。缺失 Chrome、实际用例未执行、跳过或取消均不能假绿。CI 和正式发布继续完整验收。

浏览器辅助工具记录 bundle、CSS、Chrome 启动、交互和清理耗时；同进程内按实际输入和依赖指纹复用构建，各场景仍使用独立浏览器数据和临时目录。缓存命中不代表跳过浏览器或复用历史通过结果。

## 正式验收任务

`npm run verify -- --revision <提交>` 是正式验收入口。先解析指定提交，再创建独立 Git 检出、执行 `npm ci` 和该提交的 `npm run check`。它不共享开发目录或 node_modules，不修改当前分支和暂存内容；检查开发目录的未提交更改仍需使用 check。正式验收要求目标提交已包含本入口及相应检查记录格式。

输出保留于 `logs/verify/run-*/`：顶层 summary.json 记录受验提交与结果，install.log 和 check.log 保存执行输出，source/logs/check/ 保存各阶段原始日志。source/ 是本次独立检出，成功和失败都保留现场。结果只证明记录的提交；交付目标变化后须对新提交正式复验。记录和所需产物已保存后可人工清理对应 run 目录；此目录不是应用管理工作树。

验收执行与终端观察连接分离，任务具有稳定 `runId`、源码／环境身份、阶段、心跳和原始日志。相同身份的活跃任务默认只执行一次；终端退出、超时或返回 143 后先查询原任务，不直接重新启动。

- `npm run verify -- start --revision <提交>` 启动或连接活跃任务，立即返回 JSON。
- `npm run verify -- status --run <runId>` 查询状态，不启动任务。
- `npm run verify -- wait --run <runId>` 继续等待指定任务，避免另建任务。
- `npm run verify -- --revision <提交>` 保留原来的启动／连接并等待入口。
- `--reuse-passed` 是唯一显式复用历史成功结果的入口：匹配源码、执行器、工具环境和完整证据后返回原 runId、原完成时间及 `reused:true`，不能称为本次新验收。未知环境、缺日志或源码不符均拒绝复用。

心跳过期只说明观察未确认。跨 PID 命名空间或无法确认进程身份时保持保守状态；只有核对原拥有者及其子进程已结束，才能记为 interrupted 并允许新任务。观察者退出不取消后台工作。自动取消目前不具备可靠的跨平台进程树核对，不提供成功保证；不能靠删除任务登记强行重试。

本机 Codex 工具的默认执行沙箱在命令结束时会清理整个后台进程环境，`detached` 无法越过此生命周期。通过该工具启动正式后台任务时，启动调用须使用宿主允许的持久执行入口（`exec_command` 的 `require_escalated`，遵循实际审批），查询和等待仍可使用默认沙箱。普通终端和 CI 按原命令运行。跨工具的小夹具已验证宿主启动后命令退出、第二次连接和最终完成仍对应同一 runId；不能用同一 Node 进程里的子进程测试代替这个环境核对。

依赖安装或检查修改受验源码、命令失败、检查记录缺失或不匹配时均返回非零。源码符号链接和子模块当前明确拒绝。独立检出是防止日常并行编辑污染证据的边界，不是执行不可信代码的安全沙箱。

全套测试包含样式冲突和主题矩阵；定向运行使用 `npm run styles:check`。主题矩阵必须实际启动 Chrome，缺失浏览器不能视为通过。其他测试的环境跳过仍以 test.log 为准，脚本退出零不表示所有验收条款均已运行。

CI 复用正式验收入口并沿用既有日志上传。修改检查工具或 CI 时，优先用隔离小仓库回归提交隔离、源码失效与失败日志，再固定候选提交运行全套。开发阶段先跑受影响检查，修复与审查稳定后开始完整正式验收。
