# 制作依赖与局部重制

通过统一制作入口识别修改的实际影响：

```sh
node scripts/production.mjs impact --project '/项目/中文 路径' --report /tmp/impact-report.json
```

入口及基础清单见 [项目制作命令](production.md)。`impact` 只读取项目文件、流式计算 SHA-256，并核对已声明的制作关系；不会重制、改写清单、购买配音、生图或自动导出。受影响范围用来指导局部画面重制，最终继续使用现有 ClapGrid 完整导出，没有新增增量导出。

## 记录实际使用的关系

`production.json` 的 `dependencies` 包含 `complete`、`renderInputs` 和 `nodes`。只有已核对实际使用关系后才能声明 `complete:true`。每个节点对应项目内一个普通文件，保存稳定 `id`、真实 `path`、制作时的 `sha256`、`kind`、`dependsOn`（直接消费的节点 ID），以及适用的稳定口播片段 `segmentId`。共享源或素材可以不绑定单个片段。不得用行号、显示名称或文件排序推断身份。

下面仅展示一条节点的形状；完整项目需登记全部实际制作成员及输出：

```json
{
  "id": "B-transition",
  "path": "outputs/B转场.mkv",
  "sha256": "这里填写实际文件的64位小写SHA256",
  "kind": "transition",
  "segmentId": "B",
  "dependsOn": ["A-last-frame"]
}
```

| kind | 含义与必要关系 |
| --- | --- |
| source | 制作源文件；共享源可由多个输出消费 |
| card | 制作卡；被渲染读取时记录到实际消费者，不把仅供说明的文档强行关联到画面 |
| audio | 实际配音输入；审阅输出必须关联对应配音 |
| asset | 实际使用的共享图片等素材 |
| assembly | 无音轨画面装配；必须关联对应制作源和声明的素材 |
| review | 审阅素材；必须关联对应装配与配音 |
| last-frame | 从实际片段输出取得的末帧；必须关联对应装配 |
| transition | 转场输出；必须被所属片段的实际装配消费 |

所有画面输出都须绑定清单中已有的稳定片段。图覆盖清单每个片段的 `source`、`card`、`audio`、`assembly` 与 `review`。额外消费的图片可在片段 `assets` 中列出路径，实际末帧可在 `lastFrame` 中声明，转场可在 `transitions` 中列出路径；这些声明也会核对图覆盖。一个文件只登记一个节点，共享消费者指向同一节点。

例如 A 的画面源 → A 装配 → A 末帧 → B 转场 → B 装配 → B 审阅。A 修改后，即使尚未重制的 B 文件摘要未变，也必须核对 B。B 审阅同时关联 B 配音；与这次画面变化无关的 C 和配音保持可复用。共享素材改变时沿所有实际消费者继续传播。

清单结构核对无法代替记录者检查实际消费关系。工具验证完整性声明、已知输入覆盖及必要输出关联，不声称能从任意制作程序自动推断全部运行时依赖。缺少节点、文件或已知关联、重复身份或真实路径、循环、未知片段及 `complete:false` 均明确失败，要求补齐依赖或扩大核对范围，不返回“旧输出仍有效”。

## 把渲染参数也纳入基线

文件摘要不能发现只改尺寸或帧长的情况。`dependencies.renderInputs` 保存制作该批输出时的已知渲染输入，按当前项目参数填写；下面数值只是示例：

```json
{
  "width": 1280,
  "height": 720,
  "fps": 25,
  "segments": [{ "id": "A", "frames": 50 }, { "id": "B", "frames": 60 }]
}
```

尺寸或帧率变化扩大到全部画面输出；单个稳定片段的帧长变化扩大到该片段和实际消费它的间接输出；片段顺序或身份集合变化扩大到全部输出。缺少此基线时明确待核对，并扩大到全部画面输出。`video.md`、证据说明及其他无关文字不进入这个渲染参数基线，不能仅因记录文字变化声称媒体已经改变。

摘要与参数基线代表已核对制作版本，不应为了消除待核对状态直接替换成当前值。先完成实际重制、媒体检查、边界核对及适用的确认，再保留来源和结果证据并更新项目基线。内容和审阅范围确实未变的证据可按现有规则复用。

## 使用报告安排重制与审阅

`affected.nodes` 记录已变化节点及其消费者，`affected.outputs` 记录需要重制或重新核对的画面输出，`affected.segments` 记录稳定片段范围。每项保留当前与基线摘要、直接或间接关系、`causeIds` 和 `reasonChains`；渲染参数变化另见 `details.configurationChanges`。`details.unchanged` 仅列没有被变化传播影响的节点，不会把字节仍相同但输入已变化的旧输出列为可复用。

受影响输出为 `pending` 并退出非零；图不完整为 `failed`。只有核对范围中所有项目通过且没有待核对输出时，命令退出 0。简短终端摘要及完整报告沿用统一入口，不另建检查执行器。

项目声明 `evidence` 时复用现有证据核对。受影响输入对应的旧通过记录在本次影响报告中降为待重新核对，原始记录保留；没有变化且产物、版本、范围匹配的证据保持可复用。实际重制后再次运行 `evidence`，旧 A／B 产物摘要不匹配不能通过，未变 C 与配音可显式复用。未提供证据记录时报告明确指出确认对应检查未执行，依赖核对通过不代表人工确认通过。

离线回归使用真实短视频、短音频、共享 PNG 和 A 的真实末帧制作 B 转场。重制后解码 A 首末帧、B 转场和转场相邻帧核对旧画面消失，同时检查无关素材与配音字节保留。这证明实际采样技术范围，不替代用户审美、听审、有效配音输入快照或真实宿主完整导出。相关回归通过既有 `npm test` 纳入 check／verify 和 CI；正式验收仍针对固定集成提交的独立检出。
