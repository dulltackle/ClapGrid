# 项目启动、重启与失败收尾

普通项目和刷新项目由 `tests/helpers/project.ts` 统一拥有临时目录、项目操作和生命周期；`boundProject` 独立拥有工作空间与绑定。

## 约束

- `restart(whileStopped?)` 只有在旧服务确认关闭后才执行回调；关闭失败不执行回调或替代启动，恢复失败不自动重试。
- 启动错误的 `resourcesReleased` 为 true 才允许删除目录；未知或 false 均保留目录并报告路径。跨构建边界按字段判断，不能依赖错误类的 instanceof。
- 异常退出、超时、启动未就绪均不构成释放证明。未确认任务结束时保留数据库，任何必要资源未确认时保留项目保护和目录；故障现场的保护保持到所属服务进程退出。耗尽预算后不自动重试，不直接强杀 guardian。

## 关闭预算依据

服务清理采用一次绝对截止时间，总预算 10 秒：常见请求体上限 5 秒、宿主核对上限 8 秒，以及媒体子进程 SIGTERM 后 2 秒升级机制。编辑请求已有 10 秒兜底，因此不承诺串行最坏情况必能正常结束；不能完成就失败并保留现场。这是服务关闭政策，与测试超时、fixture 兜底和媒体启动就绪等待分别设置，也不能保证系统调用或同步 SQLite 操作可被抢占。

回归入口：`project-lifecycle.spec.ts`、`service-startup.test.ts`、`service-cleanup.test.ts`。
