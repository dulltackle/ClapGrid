# 项目启动、重启与失败收尾

普通项目和刷新项目由 `tests/helpers/project.ts` 统一拥有临时目录、项目操作和生命周期。Playwright 的 worker fixture `projectServer` 分别提供源码启动及带身份的真实构建产物；刷新 adapter 仅负责构建及其构建目录。`boundProject` 仍独立拥有工作空间与绑定。

`restart(whileStopped?)` 只有在旧服务确认关闭后才执行回调，随后按原目录和端口恢复。回调失败仍恢复，单独传播原错误；回调与恢复同时失败使用包含阶段的 AggregateError。关闭失败不执行回调或替代启动，恢复失败不自动重试。

服务及初始化模块负责部分启动资源，fixture 负责自己的目录。启动错误的 `resourcesReleased` 为 true 才允许 fixture 删除目录；未知或 false 均保留目录并报告路径。判断跨构建边界按字段进行，不能依赖错误类的 instanceof。正常关闭以完整关闭 Promise 成功为准。

服务清理采用一次绝对截止时间，总预算 10 秒。选择依据为常见请求体的 5 秒上限、宿主核对的 8 秒上限，以及媒体子进程既有 SIGTERM 后 2 秒升级机制。编辑请求已有 10 秒兜底，因此这里不承诺串行最坏情况必能正常结束；先取消业务、排空请求，再使用剩余预算确认媒体退出，不能完成就失败并保留现场。这是服务关闭政策，与测试超时、fixture 的测试兜底和 15 秒媒体启动就绪等待分别设置。预算不能保证系统调用或同步 SQLite 操作可被抢占。

先停止接收请求、撤销编辑连接，立即发起业务关闭以取消配音、导出，再等待 HTTP 和 Vite 关闭。业务关闭等待在途请求及任务实际结束后关闭数据库。媒体守护进程沿既有 IPC 断开流程取消并等待媒体子进程退出；确认 worker 正常退出和无遗留活动标记后，才能释放服务所有权。异常退出、超时、启动未就绪均不构成释放证明。服务所有权保持强引用，失败结果被回收也不会意外解锁。

每步失败都会汇集错误并尝试安全的后续步骤。所有异步等待共用剩余预算；耗尽预算后仍向 guardian 发送关闭请求，但不会将请求发送当作退出成功。未确认任务结束时保留数据库，任何必要资源未确认时保留项目保护和目录。超时后不自动重试，不直接强杀 guardian。故障现场的保护一直保持到所属服务进程退出，后续恢复应先确认旧媒体及任务实际结束。

回归入口：`project-lifecycle.spec.ts` 覆盖两种真实 adapter、重启错误组合、关闭失败与目录归属；`service-startup.test.ts` 通过真实数据库解析失败及配音取消等待验证初始化和任务边界；`service-cleanup.test.ts` 独立运行最小 Vitest suite，检查具体原生失败、目录、HTTP、项目保护、守护进程出生身份及退出、独立项目存活。超时场景先人为延迟 HTTP 回执 1.8 秒，再暂停本例 guardian，核对清理仍在约 10 秒返回；恢复 guardian 后确认其自然退出，不以兜底强杀取得通过。HTTP 关闭耗尽预算的另一场景核对配音取消仍已发出。实际时长写入原生 Vitest metadata 的 `serviceCleanup`。

既有 `panel-refresh.spec.ts`、配音注入测试、`workspace-panel.spec.ts` 和 `lifecycle-export.test.ts` 保留身份差异、工作空间绑定及真实媒体退出／拒绝不安全恢复保障。完整候选和 CI 结论以对应提交的实际运行结果为准。
