# 有界等待与资源清理

遵循 ADR0011；正常耗时是观察结果，不设提速门槛。具体预算以 `vitest.config.ts` 与 `tests/helpers/` 中的常量为准。

## 规则

- 不使用无限 `testTimeout` / `hookTimeout`。条件等待使用 `expect.poll` / `vi.waitFor`；提交、启动和写入动作在观察回调之外只执行一次，等待须以本次操作的完成为条件。
- 外部命令使用可取消的异步调用，接入 `TestContext.signal`，在 `spawn` 返回时同步记录出生身份。清理只作用于本例确认拥有的进程；身份不明或退出未确认时测试失败，并保留目录与拥有权证据。
- 每例项目资源共享一次绝对截止时间，多个钩子不各领一份预算；同阶段的独立资源都获得尝试机会，全部关闭及退出确认后才删除目录。
- 不引入产品事件、可注入时钟、通用等待器、执行器、报告格式或结果认证。受控竞态、心跳、连接存活和停止后的迟到写入观察保留完整时间窗口。
- 不以延长等待或增加重试消除竞态失败。

## 预算依据

| 边界 | 依据 |
| --- | --- |
| Vitest 默认测试 15 秒 | 类型、HTTP／SQLite、短 CLI 和普通媒体场景按全套实际运行核对 |
| 原生条件轮询 5 秒 | 只观察状态；具体恢复或导出保留 10／60 秒有限例外 |
| 每例项目清理总计 8 秒 | 连接、业务／服务和进程兜底分阶段共享 |
| 命令终止 | SIGTERM 后短暂等待再有限升级 SIGKILL，并确认原身份退出 |
| 独立异常运行 | 外层必须观察实际退出；需要外层兜底终止时测试失败，不计为自行收尾成功 |

少数纯同步的真实编码器替身调用保留 `timeout` 加 `killSignal: 'SIGKILL'`；这不是以只发送 SIGTERM 的同步 timeout 证明返回上界。

## 验证入口

独立异常专项：`npx vitest run tests/bounded-run.test.ts tests/command-exit.test.ts`。

用户取消专项通过 Vitest 原生 `cancelCurrentRun('keyboard-input')` 触发。非交互 CLI 的直接 SIGINT 是框架立即退出路径，不作为协作清理成功的证据；SIGKILL、宿主强制终止或断电也不提供清理已完成的保证。
