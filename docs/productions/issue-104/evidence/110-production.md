本组落实 #110，使用 #105 当前制作基线。原文、稳定片段身份、声音与任务输入、原MP3、146帧总长、完整字幕、骨几何、裂隙、纹理及放大图时序保持一致，只有 `motion.slow` 改变承重箭头移动时间。两卡的 `id` 和版本字段只是产物标识，不渲染在画面里。

现行声音证据在 `110-current-speech.json`，带实际MCP采集起止时间及原始文件校验；本次重新探测原音频，并未以历史 valid 或旧秒数作为当前证据。声音仍为原速 vivi，未请求重制配音。入口 `entry110.tsx` 直接复用既有 `FH10.tsx`，不改共享源或产品。

## 可复现步骤

制作目录内恢复锁定依赖后，执行：

```sh
node run110.mjs
```

脚本实测当前卡中原音频，分别生成 `FH10-before-*` 与 `FH10-slow-*` 装配/审阅媒体及无损PNG。装配无音轨、无旁白字幕；审阅有原速配音及完整字幕。正式MP4为1920×1080、30fps；WebM是960×540浏览器审阅副本。采样帧是0、71、84、94、104、115及实际末帧，ROI预先由原型箭头几何确定为正式像素 `[752,55,890,166]`。比较只覆盖这些时点，不扩大为逐帧证明。

两个独立档案为 `/home/forclaw/tmp/implement-spec-104/archives/fh10-before-v1` 与 `fh10-slow-v2`。修改前版本的前版是 `fh10-v1`，放慢版的前版是 `fh10-before-v1`。各自保存原声、文案、制作卡、源、已安装依赖资源包、中文字体/许可、参考与生成来源、当前输入、审阅范围、完整校验清单。版本另存，旧版保留至试点结束。

从修改前完整档案复制到独立恢复目录，先核对全套文件与输入，再恢复依赖并重渲染：

```sh
python3 verify110.py /home/forclaw/tmp/implement-spec-104/110-restore-before
tar -xzf dependency-resources-linux-x64.tgz
node run110.mjs --before-only
```

复现后重新记录产物校验并探测、全长解码、播放。压缩视频字节相等不是通过条件。恢复只在独立目录，不迁入、覆盖或导入当前项目；如需要接回，协调者另查当前原片段身份、文字、声音和有效配音。

## 中断与异常边界

`verify110.py` 只读判断清单各文件完整性、当前输入和制作完成记录。缺失/校验错项保持“待核对”；文案或声音不匹配时，相关配音、字幕、媒体和卡保持待核对，而完整源、字体、参考可复用；缺完成记录时，产物待核对，不自动视为制作成功。

异常演练只修改档案副本，分别移除原声、破坏媒体校验、改变待核对现行文案、改变声音输入、删除完成记录；原档案和当前项目保持不动。每次输出异常项及仍可复用项，不以未失败的文件数量代替整套完成。

## 审阅范围

改了什么：仅放慢箭头；新增两版档案、区域/音轨对比和真实回退/异常演练证据。之前确认过什么：#96旁白、#97视觉规则、#100原型画面。当前箭头节奏、前后衔接与人工听审、全片终审分别记录，技术演练不代签人工作品判断；#112汇合局部动作复审和全片审阅。恢复旧版只恢复其原有范围，新修改不继承旧确认。

独立审查发现原卡的关联字段误指 #105 基线。当前卡已分别指向自己的 FH10-before/FH10-slow 装配与审阅文件；原封存 `fh10-before-v1`、`fh10-slow-v2` 保留，其旧角色映射在新版检查下为待核对。修正版另存 `fh10-before-v2`（前版 before-v1）与 `fh10-slow-v3`（前版 slow-v2），媒体实际复制并逐文件SHA确认未变。恢复目录只补映射/版本/清单，原卡与清单精确备份在 `110-role-fix/originals/restore`。新 `verify110.py` 同时检查真实文件的角色、渲染输入与完成记录；已能拒绝即使重新计算卡SHA后仍误指旧基线的自洽清单。现行审阅入口使用修正版，未重渲染或改变声音/画面。
